（Kafka-11）Kafka-Kraft 模式

Dec 24, 2023
阅读时长: 2 分钟

一、Kafka-Kraft 模式

Kafka 现有架构，元数据在 zookeeper 中，运行时动态选举 controller，由controller 进行 Kafka 集群管理。Kafka-Kraft 模式架构不再依赖 zookeeper 集群，而是用三台 controller 节点代替 zookeeper，元数据保存在 controller 中，由 controller 直接进行 Kafka 集群管理。

这样做的好处有以下几个：

  • Kafka 不再依赖外部框架，而是能够独立运行；
  • controller 管理集群时，不再需要从 zookeeper 中先读取数据，集群性能上升；
  • 由于不依赖 zookeeper，集群扩展时不再受到 zookeeper 读写能力限制；
  • controller 不再动态选举，而是由配置文件规定。这样我们可以有针对性的加强controller 节点的配置，而不是像以前一样对随机 controller 节点的高负载束手无策。

二、Kafka-Kraft集群部署

首先，我们停止原先的Kafka集群

[admin@hadoop1 ~]$$ mykafka stop
 --------停止 hadoop1 Kafka-------
 --------停止 hadoop2 Kafka-------
 --------停止 hadoop3 Kafka-------

在hadoop1、hadoop2、hadoop3上解压

[admin@hadoop1 kafka_kraft]$ mkdir /opt/module/kafka_kraft
[admin@hadoop1 kafka_kraft]$ tar -zxvf kafka_2.12-3.0.2.tgz -C /opt/module/kafka_kraft
##创建日志目录
[admin@hadoop1 kafka_2.12-3.0.2]$ mkdir /opt/module/kafka_kraft/kafka_2.12-3.0.2/data

修改/opt/module/kafka_kraft/kafka_2.12-3.0.2/config/kraft/server.properties 配置文件的以下内容：

[admin@hadoop1 kraft]$ vim /opt/module/kafka_kraft/kafka_2.12-3.0.2/config/kraft/server.properties

############################# Server Basics #############################

# The role of this server. Setting this puts us in KRaft mode
#kafka 的角色（controller 相当于主机、broker 节点相当于从机，主机类似 zk 功 能）
process.roles=broker,controller

# The node id associated with this instance's roles
#节点 ID
node.id=1

# The connect string for the controller quorum
#全 Controller 列表
controller.quorum.voters=1@hadoop1:9093,2@hadoop2:9093,3@hadoop3:9093

############################# Socket Server Settings #############################

#broker 对外暴露的地址
advertised.listeners=PLAINTEXT://hadoop1:9092

############################# Log Basics #############################

# A comma separated list of directories under which to store log files
#broker 对外暴露的地址
log.dirs=/opt/module/kafka_kraft/kafka_2.12-3.0.2/data

注意：hadoop2、hadoop3节点的以下参数要区别于hadoop1节点：

#hadoop2
node.id=2
advertised.listeners=PLAINTEXT://hadoop2:9092

#hadoop3
node.id=3
advertised.listeners=PLAINTEXT://hadoop3:9092

三、初始化集群数据目录

（1）首先生成存储目录唯一 ID。

[admin@hadoop2 kafka_2.12-3.0.2]$  bin/kafka-storage.sh random-uuid
jGhV2AizS_GmKyvfjdXs0g

（2）用该 ID 格式化 kafka 存储目录（三台节点）。

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-storage.sh format -t jGhV2AizS_GmKyvfjdXs0g -c /opt/module/kafka_kraft/kafka_2.12-3.0.2/config/kraft/server.properties

[admin@hadoop2 kafka_2.12-3.0.2]$ bin/kafka-storage.sh format -t jGhV2AizS_GmKyvfjdXs0g -c /opt/module/kafka_kraft/kafka_2.12-3.0.2/config/kraft/server.properties

[admin@hadoop3 kafka_2.12-3.0.2]$ bin/kafka-storage.sh format -t jGhV2AizS_GmKyvfjdXs0g -c /opt/module/kafka_kraft/kafka_2.12-3.0.2/config/kraft/server.properties

四 Kafka启停脚本（root创建）

创建启停脚本文件：

#[root@hadoop1 bin]# vim mykafka_kraft

#! /bin/bash
case $1 in
"start"){
 for i in hadoop1 hadoop2 hadoop3
 do
 echo " --------启动 $i Kafka-------"
 ssh $i "/opt/module/kafka_kraft/kafka_2.12-3.0.2/bin/kafka-server-start.sh -daemon /opt/module/kafka_kraft/kafka_2.12-3.0.2/config/kraft/server.properties"
 done
};;
"stop"){
 for i in hadoop1 hadoop2 hadoop3
 do
 echo " --------停止 $i Kafka-------"
 ssh $i "/opt/module/kafka_kraft/kafka_kraft/kafka_2.12-3.0.2/bin/kafka-server-stop.sh "
 done
};;
esac

为脚本文件授权：

[root@hadoop1 bin]#chmod 755 mykafka

然后启动集群

[admin@hadoop1 ~]$ mykafka_kraft start
 --------启动 hadoop1 Kafka-------
 --------启动 hadoop2 Kafka-------
 --------启动 hadoop3 Kafka-------

五、集群测试

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-topics.sh --bootstrap-server hadoop1:9092 --create --partitions 3 --replication-factor 2 --topic first-kraft
Created topic first-kraft.

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-topics.sh --bootstrap-server hadoop1:9092 --list
first-kraft
