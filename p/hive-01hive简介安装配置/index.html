一、Hive简介

Hive是由Facebook开源，基于Hadoop的一个数据仓库工具，可以将结构化的数据文件映射为一张表，并提供类SQL查询功能。

Hive是一个Hadoop客户端，用于将HQL（Hive SQL）转化成MapReduce程序。

  • （1）Hive中每张表的数据存储在HDFS
  • （2）Hive分析数据底层的实现是MapReduce（也可配置为Spark或者Tez）
  • （3）执行程序运行在Yarn上

二、Hive架构原理

  • （1）Hive Client（Hive客户端）：可以直接使用CLI（命令行客户端）来访问hive数据库、也可以使用JDBC、ODBC的客户端通过HiveServer2服务来访问hive数据库。
  • （2）HiveServer2：提供JDBC、ODBC的访问接口、用户认证功能。
  • （3）Metastore（元数据）：数据库（默认是default）、包含表名、表的拥有者、列/分区字段、表的类型（是否是外表）、表的数据所在目录等。默认存储在自带的derby数据库中，由于derby数据库只支持单客户端访问，生产环境中为了多人开发，推荐使用MySQL存储Metastore。
  • （4）Driver（驱动器）：用于解析HQL（Hive SQL）转化为MapReduce程序。

三、前期准备

3.1 环境规划

  • 1、Metastore：默认数据库是derby，由于derby数据库只支持单客户端访问，所以我们将Hive的元数据改为用MySQL存储。
  • 2、由于CLI（command-line interface）命令行客户端只能在安装了hadoop服务的机器上访问，不利于后期开发过程中使用Hive数据库，所以我们配置HiveServer2服务来连接Hive。

4.5 配置hiveserver2服务

Hive的hiveserver2服务的作用是提供jdbc/odbc接口，为用户提供远程访问Hive数据的功能，例如用户期望在个人电脑中访问远程服务中的Hive数据，而不用使用xheel等工具来连接服务器，就需要用到Hiveserver2。

所以此时需考虑一个问题：在远程访问Hive数据时，客户端并未直接访问Hadoop集群，而是由Hivesever2代理访问。由于Hadoop集群中的数据具备访问权限控制，所以此时需考虑一个问题：那就是访问Hadoop集群的用户身份是谁？是Hiveserver2的启动用户？还是客户端的登录用户？此处就涉及了Hive模拟用户的功能。

Hiveserver2的hive.server2.enable.doAs参数决定模拟成哪个用户。若启用，则Hiveserver2会模拟成客户端的登录用户去访问Hadoop集群的数据，不启用，则Hivesever2会直接使用启动用户访问Hadoop集群数据。模拟用户的功能，默认是开启的。

注意：HiveServer2服务必须能够连接hadoop集群。这样才能代理客户端与hadoop集群交互。

hivesever2的模拟用户功能，依赖于Hadoop提供的proxy user（代理用户功能），只有Hadoop中的代理用户才能模拟其他用户的身份访问Hadoop集群。因此，需要将hiveserver2的启动用户设置为Hadoop的代理用户。

配置步骤如下：

1、修改hadoop1配置文件core-site.xml,添加如下配置，并分发文件。

<!--配置所有hadoop节点的admin用户都可作为代理用户-->
<property>
    <name>hadoop.proxyuser.admin.hosts</name>
    <value>*</value>
</property>
<!--配置admin用户能够代理的用户组为任意组-->
<property>
    <name>hadoop.proxyuser.admin.groups</name>
    <value>*</value>
</property>
<!--配置admin用户能够代理的用户为任意用户-->
<property>
    <name>hadoop.proxyuser.admin.users</name>
    <value>*</value>
</property>

[admin@hadoop1 hadoop]$ xsync core-site.xml
##重启hadoop集群
[admin@hadoop1 apache-hive-3.1.3-bin]$ myhadoop stop
[admin@hadoop1 apache-hive-3.1.3-bin]$ myhadoop start

2、在hadoop1的hive-site.xml文件中添加如下配置信息

<!-- 指定hiveserver2连接的hive 服务的host -->
<property>
    <name>hive.server2.thrift.bind.host</name>
    <value>hadoop1</value>
</property>
<!-- 指定hiveserver2连接的端口号 -->
<property>
    <name>hive.server2.thrift.port</name>
    <value>10000</value>
</property>

3、启动hiveserver2服务器

[admin@hadoop1 apache-hive-3.1.3-bin]$ nohup bin/hiveserver2 &

[admin@hadoop1 bin]$ jps -ml|grep HiveServer2

4.7 配置metastore服务

Hive的metastore服务的作用是为Hive CLI或者Hiveserver2提供元数据访问接口。metastore有两种运行模式，分别为嵌入式模式和独立服务模式。目前为止我们都是使用的嵌入式模式（即客户端直接访问元数据库）。

4.7.1 metastore运行模式

嵌入式模式（默认）：只需保证Hiveserver2和每个Hive CLI的配置文件hive-site.xml中包含连接元数据库所需要的驱动参数即可。

独立服务模式（注意：图中的metastore是服务，而不是数据库名称）：

生产环境中，不推荐使用嵌入式模式。嵌入式模式下，每个Hive CLI都需要直接连接元数据库，当Hive CLI较多时，数据库压力会比较大。

4.7.2 metastore服务配置及启动

在hadoop1的hive-site.xml中配置如下参数：

<!-- 指定metastore服务的地址 -->
<property>
	<name>hive.metastore.uris</name>
	<value>thrift://hadoop1:9083</value>
</property>

主机名需要改为metastore服务所在节点，端口号无需修改，metastore服务的默认端口就是9083。**配置文件中有此参数时，hive就会默认通过metastore服务访问元数据库。**但是metastore服务所在节点必须配置JDBC参数。

然后启动metastore服务：

[admin@hadoop1 conf]$ nohup hive --service metastore &

[admin@hadoop1 conf]$ jps -ml|grep HiveMetaStore
5079 org.apache.hadoop.util.RunJar /opt/module/apache-hive-3.1.3-bin/lib/hive-metastore-3.1.3.jar org.apache.hadoop.hive.metastore.HiveMetaStore

再次使用DataGrip连接即可。

4.9 Hive常见属性配置

4.9.1 Hive的JVM堆内存设置

新版本的Hive启动的时候，默认申请的JVM堆内存大小为256M，JVM堆内存申请的太小，导致后期开启本地模式，执行复杂的SQL时经常会报错：java.lang.OutOfMemoryError: Java heap space

（1）修改$HIVE_HOME/conf下的hive-env.sh.template为hive-env.sh

$ mv hive-env.sh.template hive-env.sh

将hive-env.sh其中的参数 export HADOOP_HEAPSIZE修改为2048，重启Hive

export HADOOP_HEAPSIZE=2048

然后重启Hive服务即可。

（2）Hive的计算是依赖hadoop yarn的，一般会把yarn的虚拟内存检查功能关闭。

$ vim yarn-site.xml

添加以下内容：

<!--关闭虚拟内存检查-->
<property>
   <name>yarn.nodemanager.vmem-check-enabled</name>
   <value>false</value>
</property>

$ xsync yarn-site.xml

然后重启Hadoop集群。

我们在安装mysql时已经将mysql设置为了utf-8模式，但是我们发现数据库中的中文依然是乱码：

而且对应的mysql数据库TABLE_PARAMS表（存储了所有表的注释）记录，中文也是乱码（此处用的dbeaver，DataGrip看不到编码）。

发现表字符集是latin1，我们不是已经设置UTF-8了吗？这是因为，我们在进行Hive初始化MySQL存储元数据库时会使用hive的初始化脚本：

/opt/module/apache-hive-3.1.3-bin/scripts/metastore/upgrade/mysql目录下的hive-schema-3.1.0.mysql.sql文件，SQL语句中指定了编码为latin1。

5.2 中文乱码解决方案

知道了问题原因我们就可以解决了。可以通过修改默认脚本的方式，也可以直接修改已经生成的metastore数据库。

我们采用第二种，这样不用改动hive的内容，避免其他问题。（注意需要把之前的数据库删除了重新建，因为之前的元数据已经存储进去了乱码的形式，所以查的话就给你显示之前的了）

先关闭hive服务。然后删除数据库。

mysql> drop database metastore;
Query OK, 74 rows affected (5.03 sec)

mysql> create database metastore;
Query OK, 1 row affected (0.00 sec)

重新进行初始化：

[admin@hadoop1 apache-hive-3.1.3-bin]$ bin/schematool -dbType mysql -initSchema -verbose

修改mysql数据库表字段注解和表注解

alter table COLUMNS_V2 modify column COMMENT varchar(256) character set utf8;
alter table TABLE_PARAMS modify column PARAM_VALUE varchar(1000) character set utf8;

修改mysql数据库分区字段注解

alter table PARTITION_PARAMS modify column PARAM_VALUE varchar(1000) character set utf8;

修改mysql数据库索引注解

alter table PARTITION_KEYS modify column PKEY_COMMENT varchar(1000) character set utf8;

登录hive数据库，再次执行hive建表语句

create table phone_data
(
	id int,
	phone string,
	ip string,
	website string,
	upFlow int,
	downFlow int,
	status string
);

alter table phone_data set tblproperties ('comment' = '流量表');

这样就变成中文了：
