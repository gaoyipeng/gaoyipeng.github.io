Flume 负载均衡和故障转移

Nov 03, 2023
阅读时长: 3 分钟

一、负载均衡和故障转移

  • Sink Processor 共有三种类型，分别是Default SinkProcessor 、LoadBalancing SinkProcessor 和 Failover SinkProcessor。

    • Default SinkProcessor 对应的是单个的 Sink
    • LoadBalancing SinkProcessor 和Failover SinkProcessor 对应的是 Sink Group
    • LoadBalancing SinkProcessor 可以实现负载均衡的功能，Failover SinkProcessor 可以实现故障转移的功能。

    （补充）：sink group 定义：

1.1 Flume 故障转移(failover )

需求规划：

  • Flume-1 监控hadoop1节点的 hive日志
  • Flume-1 将变动内容传递给 Flume-2 （hadoop2节点）或者 Flume-3（hadoop3节点），Flume-2，Flume-3负责打印内容到控制台.
  • Flume-2权重高、Flume-3权重低，默认Flume-2工作，如果Flume-2异常，则Flume-3继续工作。

（1）提前准备目录

## 用于存放配置文件 /opt/module/apache-flume-1.9.0-bin/job/group2_failover
[admin@hadoop1 job]$ mkdir group2_failover

（2）在group2_failover目录下创建3个Agent进程配置文件。

  • ​ Flume-1对应Hadoop1的【 flume-exec-flume.conf】：配置 1 个 exec source 和 1 个 channel、1 个 sink group（2 个 sink），分别输送给flume-flume-console1 和 flume-flume-console2。
  • ​ Flume-2对应Hadoop2的【flume-flume-console1.conf】：配置上级 Flume 输出的 Source，输出是到本地控制台。
  • ​ Flume-3对应Hadoop3的【flume-flume-console2.conf】：配置上级 Flume 输出的 Source，输出是到本地控制台。

3个配置文件如下：

【 flume-exec-flume.conf】
# Name the components on this agent
a1.sources = r1
a1.channels = c1
a1.sinkgroups = g1
a1.sinks = k1 k2

# Describe/configure the source
a1.sources.r1.type = exec
a1.sources.r1.command = tail -F /opt/module/apache-hive-3.1.3-bin/logs/hive.log
a1.sources.r1.shell = /bin/bash -c

##sinkgroups规则配置：Failover，并配置k1,k2权重
a1.sinkgroups.g1.processor.type = failover
a1.sinkgroups.g1.processor.priority.k1 = 10
a1.sinkgroups.g1.processor.priority.k2 = 5
a1.sinkgroups.g1.processor.maxpenalty = 10000

# Describe the sink
a1.sinks.k1.type = avro
a1.sinks.k1.hostname = hadoop2
a1.sinks.k1.port = 4141

a1.sinks.k2.type = avro
a1.sinks.k2.hostname = hadoop3
a1.sinks.k2.port = 4142

# Describe the channel
a1.channels.c1.type = memory
a1.channels.c1.capacity = 1000
a1.channels.c1.transactionCapacity = 100

# Bind the source and sink to the channel 
a1.sources.r1.channels = c1
##注意此处需要sinkgroups绑定了2个sink
a1.sinkgroups.g1.sinks = k1 k2
a1.sinks.k1.channel = c1
a1.sinks.k2.channel = c1

【flume-flume-console1.conf】
# Name the components on this agent
a2.sources = r1
a2.sinks = k1
a2.channels = c1
# Describe/configure the source
a2.sources.r1.type = avro
a2.sources.r1.bind = hadoop2
a2.sources.r1.port = 4141
# Describe the sink
a2.sinks.k1.type = logger
# Describe the channel
a2.channels.c1.type = memory
a2.channels.c1.capacity = 1000
a2.channels.c1.transactionCapacity = 100
# Bind the source and sink to the channel
a2.sources.r1.channels = c1
a2.sinks.k1.channel = c1

【flume-flume-console2.conf】
# Name the components on this agent
a3.sources = r1
a3.sinks = k1
a3.channels = c2

# Describe/configure the source
a3.sources.r1.type = avro
a3.sources.r1.bind = hadoop3
a3.sources.r1.port = 4142

# Describe the sink
a3.sinks.k1.type = logger

# Describe the channel
a3.channels.c2.type = memory
a3.channels.c2.capacity = 1000
a3.channels.c2.transactionCapacity = 100

# Bind the source and sink to the channel
a3.sources.r1.channels = c2
a3.sinks.k1.channel = c2

（3）分别用启动对应的 flume Agent进程：flume-exec-flume，flume-flume-console1，flume-flume-console2。

注意先后顺序，flume-exec-flume要最后启动，它依赖后2个进程。

##hadoop2
[admin@hadoop1 apache-flume-1.9.0-bin]$ bin/flume-ng agent --conf conf/ --name a2 --conf-file job/group2_failover/flume-flume-console1.conf -Dflume.root.logger=INFO,console
##hadoop3
[admin@hadoop1 apache-flume-1.9.0-bin]$ bin/flume-ng agent --conf conf/ --name a3 --conf-file job/group2_failover/flume-flume-console2.conf -Dflume.root.logger=INFO,console
##hadoop1
[admin@hadoop1 apache-flume-1.9.0-bin]$ bin/flume-ng agent --conf conf/ --name a1 --conf-file job/group2_failover/flume-exec-flume.conf &

经过测试发现，只有hadoop2这台机器有日志打印。

如果kill 掉hadoop2的进程（只需在hadoop2上Ctrl+C即可退出），就可以看到hadoop3这台机器有日志打印了。

这样就实现了故障转移。

1.2 Flume 负载均衡(load_balance)

注意：由于channels到sink的数据流工作原理是，sink主动到channels拉取数据，这里说的负载均衡指的是sink的负载，多个sink轮流去拉取，所以实际工作中并不是sink轮流输出，而是要看在sink负载工作时，channels是否正好有数据。

我们在故障转移的示例基础上进行负载均衡的演示。

[admin@hadoop1 job]$ mkdir group2_load_balance
[admin@hadoop1 job]$ cp group2_failover/flume-exec-flume.conf group2_load_balance/flume-exec-flume2.conf
[admin@hadoop1 job]$ vim group2_load_balance/flume-exec-flume2.conf

只需修改【 flume-exec-flume2.conf】文件的以下部分：

##sinkgroups规则配置：Failover，并配置k1,k2权重
a1.sinkgroups.g1.processor.type = failover
a1.sinkgroups.g1.processor.priority.k1 = 10
a1.sinkgroups.g1.processor.priority.k2 = 5
a1.sinkgroups.g1.processor.maxpenalty = 10000

修改为：
a1.sinkgroups.g1.processor.type = load_balance
##退避属性：如果当前sink如果未拉到数据，则未来一段时间该sink不工作，可选。
#a1.sinkgroups.g1.processor.backoff = true
##最大退避时间，避免节点由于退避时间太长导致接节点不可用
#a1.sinkgroups.g1.processor.selector.maxTimeOut = 30000

然后启动flume

##hadoop2
[admin@hadoop1 apache-flume-1.9.0-bin]$ bin/flume-ng agent --conf conf/ --name a2 --conf-file job/group2_failover/flume-flume-console1.conf -Dflume.root.logger=INFO,console
##hadoop3
[admin@hadoop1 apache-flume-1.9.0-bin]$ bin/flume-ng agent --conf conf/ --name a3 --conf-file job/group2_failover/flume-flume-console2.conf -Dflume.root.logger=INFO,console
##hadoop1
[admin@hadoop1 apache-flume-1.9.0-bin]$ bin/flume-ng agent --conf conf/ --name a1 --conf-file job/group2_load_balance/flume-exec-flume2.conf &

此时hadoop2、hadoop3均可以看到日志打印了。
