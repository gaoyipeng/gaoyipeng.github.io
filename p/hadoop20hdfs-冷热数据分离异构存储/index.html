HDFS 冷热数据分离（异构存储）

Sep 05, 2023
阅读时长: 2 分钟

一、冷热数据分离

冷热数据分离：不同的数据，存储在不同类型的硬盘中，达到最佳性能。比如有些我们不常用的数据，可以找一个普通磁盘存储，而经常使用的则可以存放在固态硬盘中。

1.1 HDFS的存储类型

  • RAM_DISK：（内存镜像文件系统）
  • SSD：（SSD固态硬盘）
  • DISK：（普通磁盘，在HDFS中，如果没有主动声明数据目录存储类型默认都是DISK）
  • ARCHIVE：（没有特指哪种存储介质，主要的指的是计算能力比较弱而存储密度比较高的存储介质，用来解决数据量的容量扩增的问题，一般用于归档）

1.2 HDFS的存储策略

策略ID 策略名称 副本分布 说明
15 Lazy_Persist RAM_DISK:1，DISK:n-1 一个副本保存在内存RAM_DISK中，其余副本保存在磁盘中。
12 All_SSD SSD:n 所有副本都保存在SSD中。
10 One_SSD SSD:1，DISK:n-1 一个副本保存在SSD中，其余副本保存在磁盘中。
7 Hot(default) DISK:n 所有副本保存在磁盘中，这也是默认的存储策略。
5 Warm DSIK:1，ARCHIVE:n-1 一个副本保存在磁盘上，其余副本保存在归档存储上。
2 Cold ARCHIVE:n 所有副本都保存在归档存储上。
1 Provided Provided:1,DISK:n-1 用于在HDFS之外存储数据

策略往往和存储介质相匹配，从Lazy_Persist到Cold，设备的访问速度从快到慢。

1.3 异构存储 Shell 操作

（1）查看当前有哪些存储策略可以用,

[admin@hadoop1 hadoop-3.1.3]$ hdfs storagepolicies -listPolicies
Block Storage Policies:
        BlockStoragePolicy{PROVIDED:1, storageTypes=[PROVIDED, DISK], creationFallbacks=[PROVIDED, DISK], replicationFallbacks=[PROVIDED, DISK]}
        BlockStoragePolicy{COLD:2, storageTypes=[ARCHIVE], creationFallbacks=[], replicationFallbacks=[]}
        BlockStoragePolicy{WARM:5, storageTypes=[DISK, ARCHIVE], creationFallbacks=[DISK, ARCHIVE], replicationFallbacks=[DISK, ARCHIVE]}
        BlockStoragePolicy{HOT:7, storageTypes=[DISK], creationFallbacks=[], replicationFallbacks=[ARCHIVE]}
        BlockStoragePolicy{ONE_SSD:10, storageTypes=[SSD, DISK], creationFallbacks=[SSD, DISK], replicationFallbacks=[SSD, DISK]}
        BlockStoragePolicy{ALL_SSD:12, storageTypes=[SSD], creationFallbacks=[DISK], replicationFallbacks=[DISK]}
        BlockStoragePolicy{LAZY_PERSIST:15, storageTypes=[RAM_DISK, DISK], creationFallbacks=[DISK], replicationFallbacks=[DISK]}

（2）为指定路径（数据存储目录）设置指定的存储策略

hdfs storagepolicies -setStoragePolicy -path xxx -policy xxx

（3）获取指定路径（数据存储目录或文件）的存储策略

hdfs storagepolicies -getStoragePolicy -path xxx

（4）取消存储策略；执行改命令之后该目录或者文件，以其上级的目录为准，如果是根目录，那么就是 HOT

hdfs storagepolicies -unsetStoragePolicy -path xxx

（5）查看文件块的分布

bin/hdfs fsck xxx -files -blocks -locations

（6）查看集群节点

hadoop dfsadmin -report

1.4 存储介质配置

hadoop并不会真正的去识别存储介质是SSD还是普通磁盘，这个需要我们手动配置。

示例：生产环境下需要根据实际情况进行配置。比如/opt/module/hadoop-3.1.3/hdfsdata/ssd目录挂载的是固态硬盘，/opt/module/hadoop-3.1.3/hdfsdata/disk挂载的是普通磁盘，就可以做如下的配置。

【hdfs-site.xml】
<property>
    <name>dfs.storage.policy.enabled</name>
    <value>true</value>
</property>
<property>
<name>dfs.datanode.data.dir</name> 
    <value>>[SSD]file:///opt/module/hadoop-3.1.3/hdfsdata/ssd,[DISK]file:///opt/module/hadoop-
3.1.3/hdfsdata/disk</value>
</property>

每个节点我们可以根据实际情况进行单独配置

配置完成后，进行以下操作：

##初始化namenode
$ hdfs namenode -format

## 重启集群
myhadoop.sh start

如果我们未对某个目录进行存储策略设置，那么由于默认策略就是HOT，HDFS会选择配置了[DISK]的目录进行存储。

1.4.1 设置存储策略

如果我们设置了某个目录的存储策略，例如

$ hdfs storagepolicies -setStoragePolicy  -path /path111 -policy All_SSD

此时我们再往/path111目录上传数据时，HDFS会选择配置了[SSD]的目录进行存储。

1.4.2 修改存储策略

如果我们已经上传了文件，但是现在想要将文件降级，放到Cold策略的存储路径下，如何进行操作？

1、修改存储策略

$ hdfs storagepolicies -setStoragePolicy  -path /hdfsdata -policy Cold

此时使用命令 hdfs fsck /hdfsdata -files -blocks -locations查看文件的存储位置是不会发生变化的，需要手动进行移动。

2、手动移动文件

$ hdfs mover /hdfsdata

再次查看文件位置，就会发现，文件都移动到了ARCHIVE类型的目录下了。

注意：当我们将目录设置为 COLD 并且我们未配置 ARCHIVE 存储目录的情况下，不可以向该目录直接上传文件，会报出异常。

1.4.3 LAZY_PERSIST 策略说明

LAZY_PERSIST 策略会把一个副本保存在内存RAM_DISK中，其余副本保存在磁盘中。

由于存储到内存中，存在安全性问题，一旦系统故障，内存中的数据就会丢失，所以该策略是不推荐的。

如果需要存储到内存，需要添加配置dfs.datanode.max.locked.memory，并且设置Value不小于dfs.block.size参数值（128M）：

<property>
  <name>dfs.datanode.max.locked.memory</name>
  <value>0</value>
  <description>
    The amount of memory in bytes to use for caching of block replicas in
    memory on the datanode. The datanode's maximum locked memory soft ulimit
    (RLIMIT_MEMLOCK) must be set to at least this value, else the datanode
    will abort on startup.
    By default, this parameter is set to 0, which disables in-memory caching.
    If the native libraries are not available to the DataNode, this
    configuration has no effect.
  </description>
</property>

但是由于虚拟机max locked memory参数为64KB，参数配置过大，上传还会报错，所以我们只能修改dfs.block.size参数值。这在生产环境下是不适用的。

所以，默认情况下，当设置某个某个目录未LAZY_PERSIST 策略时，所有的文件块都是存储在 DISK上。
