登录root账号修改分发脚本 /bin/xsync：

[root@hadoop1 bin]# vim xsync
#!/bin/bash
#1. 判断参数个数
if [ $# -lt 1 ]
then
 echo Not Enough Arguement!
 exit;
fi
#2. 遍历集群所有机器
for host in hadoop1 hadoop2 hadoop3 hadoop4 hadoop5
do
 echo ==================== $host ====================
 #3. 遍历所有目录，挨个发送
 for file in $@
 do
 #4. 判断文件是否存在
 if [ -e $file ]
 then
 #5. 获取父目录
 pdir=$(cd -P $(dirname $file); pwd)
 #6. 获取当前文件的名称
 fname=$(basename $file)
 ssh $host "mkdir -p $pdir"
 rsync -av $pdir/$fname $host:$pdir
 else
 echo $file does not exists!
 fi
 done
done

修改hadoop启停脚本/bin/myhadoop(只需修改jps命令部分即可):

#!/bin/bash
if [ $# -lt 1 ]
then
 echo "No Args Input..."
 exit ;
fi
case $1 in
"start")
 echo " =================== 启动 hadoop 集群 ==================="
 echo " --------------- 启动 hdfs ---------------"
 ssh hadoop1 "/opt/module/hadoop-3.1.3/sbin/start-dfs.sh"
 echo " --------------- 启动 yarn ---------------"

 ssh hadoop2 "/opt/module/hadoop-3.1.3/sbin/start-yarn.sh"
 echo " --------------- 启动 historyserver ---------------"
 ssh hadoop1 "/opt/module/hadoop-3.1.3/bin/mapred --daemon start historyserver"
;;
"stop")
 echo " =================== 关闭 hadoop 集群 ==================="
 echo " --------------- 关闭 historyserver ---------------"
 ssh hadoop1 "/opt/module/hadoop-3.1.3/bin/mapred --daemon stop historyserver"
 echo " --------------- 关闭 yarn ---------------"
 ssh hadoop2 "/opt/module/hadoop-3.1.3/sbin/stop-yarn.sh"
 echo " --------------- 关闭 hdfs ---------------"
 ssh hadoop1 "/opt/module/hadoop-3.1.3/sbin/stop-dfs.sh"
;;
"jps")
 echo " =================== 查看 hadoop 集群服务状态 ==================="
for host in hadoop1 hadoop2 hadoop3 hadoop4 hadoop5
do
 echo =============== $host ===============
 ssh $host jps
done
;;
*)
 echo "Input Args Error..."
;;
esac

1.2 集群添加新节点

在hadoop4、hadoop5 上直接启动 DataNode和nodemanager服务，即可关联到集群。

[admin@hadoop5 hadoop-3.1.3]$ hdfs --daemon start datanode
[admin@hadoop5 hadoop-3.1.3]$ yarn --daemon start nodemanager

在hadoop1节点执行一下更新操作：

[admin@hadoop1 hadoop]$  hdfs dfsadmin -refreshNodes

二、黑名单和白名单配置

HDFS可以配置黑名单和白名单来管理集群。在白名单的主机 IP 地址可以用来存储数据。黑名单的主机 IP 地址不可以存储数据，通过配置黑名单可以实现服务器退役。

1.1 配置白名单

在NameNode 节点的/opt/module/hadoop-3.1.3/etc/hadoop目录下分别创建whitelist和blacklist文件

[admin@hadoop1 hadoop]$ vim whitelist
[admin@hadoop1 hadoop]$ vim blacklist

在whitelist中配置如下内容，表示hadoop1、hadoop2是正常的数据节点。

[admin@hadoop1 hadoop]$ cat whitelist
hadoop1
hadoop2

在 hdfs-site.xml 配置文件中增加 dfs.hosts 配置参数

<!-- 白名单 -->
<property>
 <name>dfs.hosts</name>
 <value>/opt/module/hadoop-3.1.3/etc/hadoop/whitelist</value>
</property>
<!-- 黑名单 -->
<property>
 <name>dfs.hosts.exclude</name>
 <value>/opt/module/hadoop-3.1.3/etc/hadoop/blacklist</value>
</property>

分发配置文件：

[admin@hadoop1 hadoop]$ xsync /opt/module/hadoop-3.1.3/etc/hadoop/

由于我们是第一次添加白名单，必须重启集群，不是第一次，只需要刷新NameNode节点即可，重启后查看，可以看到已经没有hadoop3、hadoop4、hadoop5节点了。

我们再把hadoop3、hadoop4、hadoop5加回去：

[admin@hadoop1 hadoop]$ cat whitelist
hadoop1
hadoop2
hadoop3
hadoop4
hadoop5

这次只需要做刷新 NameNode操作即可：

[admin@hadoop1 hadoop]$ hdfs dfsadmin -refreshNodes
Refresh nodes successful

再次查看，集群已经恢复正常：

1.2 配置黑名单退役服务器

注意：默认副本数是3，服役的节点小于等于 3，是不能退役成功的，需要修改副本数后才能退役。

我们上面已经新建了blacklist黑名单文件。我们集群有5台，我们本次准备把hadoop5退役。我们先在hadoop5上传一个文件，观察服务器退出集群后的文件变化。

1、编辑/opt/module/hadoop-3.1.3/etc/hadoop/blacklist，添加 hadoop5 到文件中。

# vim blacklist
hadoop5

然后分发配置文件（blacklist），由于不是第一次添加黑白名单，这次只需要做刷新 NameNode操作即可：

[admin@hadoop1 hadoop]$ hdfs dfsadmin -refreshNodes
Refresh nodes successful

检查Web浏览器，退役节点的状态为decommission in progress（退役中），说明数据节点正在复制块到其他节点：

等待退役节点状态为 decommissioned（所有块已经复制完成）

此时我们查看文件存储情况，可以看到文件已经从hadoo5节点转移到 hadoop3节点了。

此时就可以停止该节点及节点资源管理器。在hadoop5节点执行如下操作：

[admin@hadoop5 hadoop-3.1.3]$ hdfs --daemon stop datanode
[admin@hadoop5 hadoop-3.1.3]$ yarn --daemon stop nodemanager

再次查看，hadoop5已经不再保存数据列表了。这样就完成了服务器退出集群
