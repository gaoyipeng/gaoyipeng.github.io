（Kafka-06）Kafka 节点服役和退役

Nov 24, 2023
阅读时长: 3 分钟

一、Kafka 节点服役

我们当前Kafka分布在hadoop1、hadoop2、hadoop3，如果生产环境需要扩充集群，应该怎么做呢？

我们把hadoop4节点加入到集群中。

1.1 新节点准备及启动

上传安装包到hadoop4节点并解压：

[admin@hadoop4 config]$ tar -zxvf kafka_2.12-3.0.2.tgz -C /opt/module/

配置环境变量（root用户操作）：

[root@hadoop4 profile.d]# vim /etc/profile.d/my_env.sh

#KAFKA_HOME
export KAFKA_HOME=/opt/module/kafka_2.12-3.0.2
export PATH=$PATH:$KAFKA_HOME/bin

执行以下命令，使PATH生效：

source /etc/profile

修改kafka配置文件

提前创建数据文件夹，后续配置会用到。

[admin@hadoop4 config]$ mkdir /opt/module/kafka_2.12-3.0.2/datas

修改配置文件：

[admin@hadoop4 config]$ vim /opt/module/kafka_2.12-3.0.2/config/server.properties

修改broker.id为3，要与其他3个节点区分开。

broker.id=3
log.dirs=/opt/module/kafka_2.12-3.0.2/datas
zookeeper.connect=hadoop1:2181,hadoop2:2181,hadoop3:2181/kafka

1.2 启动新节点

然后启动hadoop4的kafka服务，

[admin@hadoop4 config]$ /opt/module/kafka_2.12-3.0.2/bin/kafka-server-start.sh -daemon /opt/module/kafka_2.12-3.0.2/config/server.properties

[admin@hadoop4 kafka_2.12-3.0.2]$ jps
10497 Kafka
306 NodeManager
32660 DataNode
10587 Jps

可以看到Kafka已经启动。并且已经注册到了zk中。

1.3 新节点主题负载均衡操作

我们新增加了hadoop4节点，但是新节点只会对新主题生效。

[admin@hadoop4 kafka_2.12-3.0.2]$ bin/kafka-topics.sh --bootstrap-server hadoop1:9092 --describe --topic first
Topic: first    TopicId: _R6Ed9eqQvWEpxtV_bvXPQ PartitionCount: 3       ReplicationFactor: 2    Configs: segment.bytes=1073741824
        Topic: first    Partition: 0    Leader: 1       Replicas: 1,0   Isr: 1,0
        Topic: first    Partition: 1    Leader: 0       Replicas: 0,2   Isr: 0,2
        Topic: first    Partition: 2    Leader: 2       Replicas: 2,1   Isr: 2,1

我们查看first主题，可以看到原有主题的数据依然是分布在原先的3台机器上，如果我们想让主题均匀分布，就需要进行负载均衡调整了。

（1）创建一个要均衡的主题（一个json文件），包含了准备均衡的topic。

[admin@hadoop1 kafka_2.12-3.0.2]$  vim topics-to-move.json

{
 "topics": [
 {"topic": "first"}
 ],
 "version": 1
}

(2)然后生成均衡计划，结果分为2部分，第一部分是当前分布情况，第二部分就是均衡计划。

注意，该命令并不能直接使主题均衡，而是会生成一份json格式的均衡计划。

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-reassign-partitions.sh --bootstrap-server hadoop1:9092 --topics-to-move-json-file topics-to-move.json --broker-list "0,1,2,3" --generate

Current partition replica assignment
{"version":1,"partitions":[{"topic":"first","partition":0,"replicas":[1,0],"log_dirs":["any","any"]},{"topic":"first","partition":1,"replicas":[0,2],"log_dirs":["any","any"]},{"topic":"first","partition":2,"replicas":[2,1],"log_dirs":["any","any"]}]}

Proposed partition reassignment configuration
{"version":1,"partitions":[{"topic":"first","partition":0,"replicas":[3,0],"log_dirs":["any","any"]},{"topic":"first","partition":1,"replicas":[0,1],"log_dirs":["any","any"]},{"topic":"first","partition":2,"replicas":[1,2],"log_dirs":["any","any"]}]}

(3)将均衡计划单独复制到一个json文件中创建副本存储计划（所有副本存储在 broker0、broker1、broker2、broker3 中）。然后执行。

[admin@hadoop1 kafka_2.12-3.0.2]$ vim increase-replication-factor.json

{"version":1,"partitions":[{"topic":"first","partition":0,"replicas":[3,0],"log_dirs":["any","any"]},{"topic":"first","partition":1,"replicas":[0,1],"log_dirs":["any","any"]},{"topic":"first","partition":2,"replicas":[1,2],"log_dirs":["any","any"]}]}

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-reassign-partitions.sh --bootstrap-server hadoop1:9092 --reassignment-json-file increase-replication-factor.json --execute
Current partition replica assignment

{"version":1,"partitions":[{"topic":"first","partition":0,"replicas":[1,0],"log_dirs":["any","any"]},{"topic":"first","partition":1,"replicas":[0,2],"log_dirs":["any","any"]},{"topic":"first","partition":2,"replicas":[2,1],"log_dirs":["any","any"]}]}

Save this to use as the --reassignment-json-file option during rollback
Successfully started partition reassignments for first-0,first-1,first-2

(4)再次查看主题详情,可以看到新的节点了：

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-topics.sh --bootstrap-server hadoop1:9092 --describe --topic first
Topic: first    TopicId: _R6Ed9eqQvWEpxtV_bvXPQ PartitionCount: 3       ReplicationFactor: 2    Configs: segment.bytes=1073741824
        Topic: first    Partition: 0    Leader: 3       Replicas: 3,0   Isr: 0,3
        Topic: first    Partition: 1    Leader: 0       Replicas: 0,1   Isr: 0,1
        Topic: first    Partition: 2    Leader: 2       Replicas: 1,2   Isr: 2,1

也可以验证副本存储计划执行情况：

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-reassign-partitions.sh --bootstrap-server hadoop1:9092 --reassignment-json-file increase-replication-factor.json --verify
Status of partition reassignment:
Reassignment of partition first-0 is complete.
Reassignment of partition first-1 is complete.
Reassignment of partition first-2 is complete.

Clearing broker-level throttles on brokers 0,1,2,3
Clearing topic-level throttles on topic first

二、Kafka 退役旧节点

2.1 退役前均衡操作

目前我们有退役前有hadoop1、hadoop2、hadoop3、hadoop4四个节点，现在准备将hadoop4节点退役，但是需要将hadoop4节点节点的topic 都转义到其他节点。

（1）创建一个要均衡的主题（一个json文件），包含了准备均衡的topic。

[admin@hadoop1 kafka_2.12-3.0.2]$  vim topics-to-move.json

{
 "topics": [
 {"topic": "first"}
 ],
 "version": 1
}

然后生成均衡计划，结果分为2部分，第一部分是当前分布情况，第二部分就是均衡计划。

（2）创建执行计划(去掉broker3节点)


[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-reassign-partitions.sh --bootstrap-server hadoop1:9092 --topics-to-move-json-file topics-to-move.json --broker-list "0,1,2" --generate
Current partition replica assignment
{"version":1,"partitions":[{"topic":"first","partition":0,"replicas":[3,0],"log_dirs":["any","any"]},{"topic":"first","partition":1,"replicas":[0,1],"log_dirs":["any","any"]},{"topic":"first","partition":2,"replicas":[1,2],"log_dirs":["any","any"]}]}

Proposed partition reassignment configuration
{"version":1,"partitions":[{"topic":"first","partition":0,"replicas":[0,1],"log_dirs":["any","any"]},{"topic":"first","partition":1,"replicas":[1,2],"log_dirs":["any","any"]},{"topic":"first","partition":2,"replicas":[2,0],"log_dirs":["any","any"]}]}

（3）创建副本存储计划（所有副本存储在 broker0、broker1、broker2 中）。

[admin@hadoop1 kafka_2.12-3.0.2]$ vim increase-replication-factor1.json

{"version":1,"partitions":[{"topic":"first","partition":0,"replicas":[0,1],"log_dirs":["any","any"]},{"topic":"first","partition":1,"replicas":[1,2],"log_dirs":["any","any"]},{"topic":"first","partition":2,"replicas":[2,0],"log_dirs":["any","any"]}]}

(4)执行副本存储计划。

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-reassign-partitions.sh --bootstrap-server hadoop1:9092 --reassignment-json-file increase-replication-factor1.json --execute
Current partition replica assignment

{"version":1,"partitions":[{"topic":"first","partition":0,"replicas":[3,0],"log_dirs":["any","any"]},{"topic":"first","partition":1,"replicas":[0,1],"log_dirs":["any","any"]},{"topic":"first","partition":2,"replicas":[1,2],"log_dirs":["any","any"]}]}

Save this to use as the --reassignment-json-file option during rollback
Successfully started partition reassignments for first-0,first-1,first-2

（5）验证副本存储计划。


[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-reassign-partitions.sh --bootstrap-server hadoop1:9092 --reassignment-json-file increase-replication-factor1.json --verify
Status of partition reassignment:
Reassignment of partition first-0 is complete.
Reassignment of partition first-1 is complete.
Reassignment of partition first-2 is complete.

Clearing broker-level throttles on brokers 0,1,2,3
Clearing topic-level throttles on topic first

再次查看主题详情:

[admin@hadoop1 kafka_2.12-3.0.2]$ bin/kafka-topics.sh --bootstrap-server hadoop1:9092 --describe --topic first
Topic: first    TopicId: _R6Ed9eqQvWEpxtV_bvXPQ PartitionCount: 3       ReplicationFactor: 2    Configs: segment.bytes=1073741824
        Topic: first    Partition: 0    Leader: 0       Replicas: 0,1   Isr: 0,1
        Topic: first    Partition: 1    Leader: 1       Replicas: 1,2   Isr: 1,2
        Topic: first    Partition: 2    Leader: 2       Replicas: 2,0   Isr: 2,0

2.2 关闭退役节点服务

在完成退役节点均衡操作后，关闭节点kafka服务即可。

[admin@hadoop4 kafka_2.12-3.0.2]$  bin/kafka-server-stop.sh

以上就是Kafka 节点服役和退役全部内容。
