那么什么时候使用where，什么时候使用having呢？答案就是需要使用组函数时使用having。

4、DDL语言

4.1创建表

命名规则：

4.1.1 建表方式一

格式：
CREATE TABLE [schema.]table
	    (column datatype [DEFAULT expr][, ...]);

eg:

CREATE TABLE dept	(
		deptno 	NUMBER(2),
		dname 	VARCHAR2(14),
		loc 	VARCHAR2(13));

4.1.2 建表方式二

使用 AS subquery 选项，将创建表和插入数据结合起来.

格式：
CREATE TABLE table
  	  [(column, column...)]
AS subquery;

eg:

复制现有的表：
create table emp1 as select * from employees;
create table emp2 as select * from employees where 1=2;
--创建的emp2是空表。
CREATE TABLE  deptbak
  AS     SELECT  employee_id, last_name， hire_date    
  		 FROM    employees
  		 WHERE   department_id = 80;

4.2 修改表

语法：

eg:

4.2.2 修改字段

语法：
ALTER TABLE table

		   [, column datatype]...);

eg:

对默认值的修改只影响今后对表的修改.

更改数据类型，要求修改的列必须为空。

4.2.3 删除字段

语法：
ALTER TABLE table
DROP COLUMN  column_name;

eg:

4.2.4 重命名字段

语法：
ALTER TABLE table_name
RENAME COLUMM old_column_name 
TO new_column_name

eg:

RENAME COLUMN  job_id TO id;

4.3 删除表

语法：DROP TABLE table_name;
  • 数据和结构都被删除
  • 所有正在运行的相关事务被提交
  • 所有相关索引被删除
  • DROP TABLE 语句不能回滚

4.4 清空表

语法： TRUNCATE TABLE table_name;
  • 删除表中所有的数据、表结构保留
  • 释放表的存储空间
  • TRUNCATE语句不能回滚，即表中数据无法恢复。

4.5 表重命名

语法：
RENAME table_name TO table_newname;
  • 执行RENAME语句改变表, 视图, 序列, 或同义词的名称

5.2 数据库事务

5.2.1 事务概念

事务：一组逻辑操作单元,使数据从一种状态变换到另一种状态。

数据库事务以一个 DML 语句的执行作为开始，以下面的其中之一作为结束：

  • COMMIT 或 ROLLBACK 语句
  • DDL 语句（自动提交）
  • 用户会话正常结束
  • 系统异常终止

5.2.2 控制事务

1、COMMIT ：提交事务

2、ROLLBACK ：回滚事务

3、SAVEPOINT

使用 SAVEPOINT 语句在当前事务中创建保存点。
使用 ROLLBACK TO SAVEPOINT 语句回滚到创建的保存点。

6、常见约束

6.1 约束分类

①列级约束只能作用在一个列上 ②表级约束可以作用在多个列上（当然表级约束也 可以作用在一个列上）

定义方式：列约束必须跟在列的定义后面，表约束不与列一起，而是单独定义。

非空(not null) 约束只能定义在列上。

6.2 常见约束

6.2.1 NOT NULL：非空约束

CREATE TABLE employees(
    employee_id    NUMBER(6),
    last_name      VARCHAR2(25) NOT NULL, --系统命名
    salary         NUMBER(8,2),
    commission_pct NUMBER(2,2),
    hire_date      DATE  CONSTRAINT emp_hire_date_nn NOT NULL --自定义约束名称
)

非空(not null) 约束只能定义在列上。

CONSTRAINT：用来定义约束名称，不使用这个，oracle会设置一个默认名称。

6.2.2 UNIQUE：唯一约束

唯一约束，允许出现多个空值：NULL。

CREATE TABLE employees(
    employee_id      NUMBER(6),
    last_name        VARCHAR2(25) UNIQUE, --列级约束、系统命名
    email            VARCHAR2(25),
    salary           NUMBER(8,2),
    commission_pct   NUMBER(2,2),
    hire_date        DATE NOT NULL,
    CONSTRAINT emp_email_uk UNIQUE(email))--表级约束、自定义约束名称
）

6.2.3 PRIMARY KEY：主键约束

不允许null ，不允许重复。

CREATE TABLE   departments(
    department_id        NUMBER(4),
    department_name      VARCHAR2(30)
    CONSTRAINT dept_name_nn NOT NULL,
    manager_id           NUMBER(6),
    location_id          NUMBER(4),
    CONSTRAINT dept_id_pk PRIMARY KEY(department_id))--表级约束、自定义主键名称
)

CREATE TABLE   departments(
    department_id        NUMBER(4) CONSTRAINT dept_id_pk PRIMARY KEY,--列级约束、自定义主键名称
    department_name      VARCHAR2(30)
    CONSTRAINT dept_name_nn NOT NULL,
    manager_id           NUMBER(6),
    location_id          NUMBER(4)
)

6.2.4 FOREIGN KEY：外键约束

CREATE TABLE employees(
    employee_id      NUMBER(6),
    last_name        VARCHAR2(25) NOT NULL,
    email            VARCHAR2(25),
    salary           NUMBER(8,2),
    commission_pct   NUMBER(2,2),
    hire_date        DATE NOT NULL,
    department_id    NUMBER(4),
    CONSTRAINT emp_dept_fk FOREIGN KEY (department_id) REFERENCES departments(department_id) on delete set null,--外键约束,级联置空
    CONSTRAINT emp_email_uk UNIQUE(email)
);

  • FOREIGN KEY: 在表级指定子表中的列

  • REFERENCES: 标示在父表中的列

    在oracle中，如果你需要删除的数据被其他数据所参照，例如上栗中的departments表中的‘departments_id’，外键约束情况下默认是不允许删除的。如果必须要删除，可以有以下两种选择：

    1、ON DELETE CASCADE(级联删除): 当父表中的列被删除时，子表中相对应的列也被删除
2、ON DELETE SET NULL(级联置空): 子表中相应的列置空

6.2.5 CHECK：自定义约束

CREATE TABLE employees(
    employee_id      NUMBER(6),
    last_name        VARCHAR2(25) NOT NULL,
    email            VARCHAR2(25),
    salary           NUMBER(8,2) CONSTRAINT emp_salary_min CHECK (salary > 5000),--自定义check约束，工资必须大于5000
    commission_pct   NUMBER(2,2),
    hire_date        DATE NOT NULL,
    department_id    NUMBER(4)
);

6.3 管理约束

使用 ALTER TABLE 语句：

  1. 添加或删除约束,但是不能修改约束。
  2. 有效化或无效化约束。
  3. 添加 NOT NULL 约束要使用 MODIFY 语句。

6.3.1 添加约束

表已经建好了，如果想要添加约束。

ALTER TABLE	 table
  ADD [CONSTRAINT constraint] type (column);
 eg:
 ALTER TABLE   employees
  ADD CONSTRAINT  emp_manager_fk 
  FOREIGN KEY(manager_id) 
  REFERENCES employees(employee_id);

6.3.2 删除约束

ALTER TABLE      employees
DROP CONSTRAINT  emp_manager_fk;

6.3.3 无效化约束

ALTER TABLE		employees
DISABLE CONSTRAINT	emp_emp_id_pk;

6.3.4 激活（有效化）约束

ENABLE 子句可将当前无效的约束激活 。

ALTER TABLE		employees
ENABLE CONSTRAINT	emp_emp_id_pk;

6.3.5 查询约束

查询表的约束有哪些：

SELECT	constraint_name, constraint_type,
	search_condition
FROM	user_constraints
WHERE	table_name = 'EMPLOYEES';

查询定义约束的列：

SELECT	constraint_name, column_name
FROM	user_cons_columns
WHERE	table_name = 'EMPLOYEES';

7、视图 View

7.1 创建视图

CREATE OR REPLACE VIEW empvu80
  (id_number, name, sal, department_id)
AS SELECT  employee_id, first_name || ' ' || last_name, 
           salary, department_id
   FROM    employees
   WHERE   department_id = 80;

正常创建的简单视图，是可以进行DML操作的，比如修改视图中的字段信息，会同步修改原表对应的记录。如果不允许修改视图，可以使用 WITH READ ONLY 选项屏蔽对视图的DML 操作。

CREATE OR REPLACE VIEW empvu10
    (employee_number, employee_name, job_title)
AS SELECT	employee_id, last_name, job_id
   FROM     employees
   WHERE    department_id = 10
   WITH READ ONLY;

7.2 删除视图

drop view view_name;

7.3 复杂视图

示例：

CREATE VIEW	dept_sum_vu
  (name, minsal, maxsal, avgsal)
AS SELECT	 d.department_name, MIN(e.salary), 
             MAX(e.salary),AVG(e.salary)
   FROM      employees e, departments d
   WHERE     e.department_id = d.department_id 
   GROUP BY  d.department_name;

7.4 视图中使用DML的规定

可以在简单视图中执行 DML 操作，当视图定义中包含以下元素之一时不能使用delete:

  • 组函数
  • GROUP BY 子句
  • DISTINCT 关键字
  • ROWNUM 伪列

当视图定义中包含以下元素之一时不能使用update：

  • 组函数
  • GROUP BY子句
  • DISTINCT 关键字
  • ROWNUM 伪列
  • 列的定义为表达式

当视图定义中包含以下元素之一时不能使insert:

  • 组函数
  • GROUP BY 子句
  • DISTINCT 关键字
  • ROWNUM 伪列
  • 列的定义为表达式
  • 表中非空的列在视图定义中未包括

8、 Top-N分析

Top-N分析可用于分页等查询。

Top-N 分析查询一个列中最大或最小的 n 个值。

SELECT [column_list], ROWNUM  
FROM   (SELECT [column_list] 
        FROM table
        ORDER  BY Top-N_column)
WHERE  ROWNUM <=  N;

对 ROWNUM 只能使用 < 或 <=, 而用 =, >, >= 都将不能返回任何数据。

例如：查询工资最高的三名员工:

SELECT ROWNUM as RANK, last_name, salary 
FROM  (SELECT last_name,salary FROM employees
       ORDER BY salary DESC)
WHERE ROWNUM <= 3;

如果需要查询工资处理40到50名间的员工怎么办，ROWNUM 不允许使用 ‘>40’这种写法。可以把rownum伪列变为实际列，然后再排序。

select *
	from(
		select rownum rn,employee_id,salary
         from(
            select employee_id,salary,last_name
            from employees
            order by salary desc)
	)
where rn <=50 and rn >40;

9、序列

序列: 可供多个用户用来产生唯一数值的数据库对象。

  • 自动提供唯一的数值
  • 共享对象
  • 主要用于提供主键值
  • 将序列值装入内存可以提高访问效率

9.1 定义序列

CREATE SEQUENCE sequence_name
       [INCREMENT BY n]  --每次增长的数值
       [START WITH n]    --从哪个值开始
       [{MAXVALUE n | NOMAXVALUE}]
       [{MINVALUE n | NOMINVALUE}]
       [{CYCLE | NOCYCLE}]     --是否需要循环
       [{CACHE n | NOCACHE}];  --是否缓存登录

eg:

CREATE SEQUENCE dept_deptid_seq
                INCREMENT BY 10
                START WITH 120
                MAXVALUE 9999
                NOCACHE
                NOCYCLE;

获取序列下一个值：

Select seq.nextval from dual;

获取序列当前值：

Select seq.currval from dual;

NEXTVAL 应在 CURRVAL 之前指定 ，否则会报CURRVAL 尚未在此会话中定义的错误。

9.2 修改序列

修改序列的增量, 最大值, 最小值, 循环选项, 或是否装入内存。

ALTER SEQUENCE dept_deptid_seq
               INCREMENT BY 20
               MAXVALUE 999999
               NOCACHE
               NOCYCLE;

修改序列的注意事项：

  • 必须是序列的拥有者或对序列有 ALTER 权限
  • 只有将来的序列值会被改变
  • 改变序列的初始值只能通过删除序列之后重建序列的方法实现

9.3 删除序列

DROP SEQUENCE dept_deptid_seq;

9.4 序列裂缝

即序列值之间出现不连贯的情况。

序列在下列情况下出现裂缝：

  • 回滚
  • 系统异常
  • 多个表同时使用同一序列

9.5 查询序列

SELECT	sequence_name, min_value, max_value, 
	increment_by, last_number
FROM	user_sequences;

如果指定NOCACHE 选项，则列LAST_NUMBER 显示序列中下一个有效的值.

10、索引

  • 一种独立于表的模式对象, 可以存储在与表不同的磁盘或表空间中。
  • 索引被删除或损坏, 不会对表产生影响, 其影响的只是查询的速度。
  • 索引一旦建立, Oracle 管理系统会对其进行自动维护, 而且由 Oracle 管理系统决定何时使用索引。用户不用在查询语句中指定使用哪个索引，
  • 在删除一个表时,所有基于该表的索引会自动被删除，
  • 通过指针加速 Oracle 服务器的查询速度。通过快速定位数据的方法，减少磁盘 I/O。

10.1 创建索引

在一个或多个列上创建索引

CREATE INDEX index
ON table (column[, column]...);

eg:
CREATE INDEX 	emp_last_name_idx
ON 		employees(last_name);

什么时候创建索引？

  • 列中数据值分布范围很广
  • 列经常在 WHERE 子句或连接条件中出现
  • 表经常被访问而且数据量很大 ，访问的数据大概占数据总量的2%到4%

下列情况不要创建索引？

  • 表很小
  • 列不经常作为连接条件或出现在WHERE子句中
  • 查询的数据大于2%到4%
  • 表经常更新

10.2 删除索引

DROP INDEX index;

10.3 查询索引

SELECT	ic.index_name, ic.column_name,
	ic.column_position col_pos,ix.uniqueness
FROM	user_indexes ix, user_ind_columns ic
WHERE	ic.index_name = ix.index_name
AND	ic.table_name = 'EMPLOYEES';

11、同义词

使用同义词访问相同的对象，方便访问其它用户的对象，缩短对象名字的长度。

CREATE [PUBLIC] SYNONYM synonym_name FOR  object;
eg:
CREATE SYNONYM e FOR employees;

使用：
select * from e;
删除同义词：
DROP SYNONYM e;

DBA 可以创建用户和修改密码，用户本人可以使用 ALTER USER 语句修改密码

ALTER USER user_name  IDENTIFIED BY new_passwd;

12.6 分配对象权限

不同的对象具有不同的对象权限 对象的拥有者拥有所有权限 对象的拥有者可以向外分配权限

 GRANT	object_priv [(columns)]
 ON		object
 TO		{user|role|PUBLIC}
 [WITH GRANT OPTION];
 
 eg:
 1、分配表 EMPLOYEES 的查询权限给用户 user_name1, user_name2
 GRANT  select ON  employees  TO   user_name1, user_name2;
 2、分配user_name1用户的departments表的查询权限给user_name2
 GRANT  select ON     user_name1.departments  TO   user_name2;

 此时user_name2可以通过 select * from user_name1.departments;来查询user_name1用户下的表。

12.7 权限转授

WITH GRANT OPTION和PUBLIC关键字。

  • WITH GRANT OPTION 使用户同样具有分配权限的权利
--scott用户可以把departments表的select, insert权限，授予别人
GRANT  select, insert
ON     departments
TO     scott
WITH   GRANT OPTION;
  • PUBLIC关键字。向数据库中所有用户分配权限
--scott用户的departments的查询权限给所有人
GRANT  select
ON	  scott.departments
TO	  PUBLIC;

12.8 权限回收

  • 使用 REVOKE 语句收回权限
  • 使用 WITH GRANT OPTION 子句所分配的权限同样被收回
REVOKE {privilege [, privilege...]|ALL}
ON	  object
FROM   {user[, user...]|role|PUBLIC}
[CASCADE CONSTRAINTS];

eg :
REVOKE select on scott.departments FROM user_name;

13、SET 操作符

将多个查询用 SET 操作符连接组成一个新的查询。

  • UNION / UNION ALL （取集合）
  • INTERSECT （交集）
  • MINUS （差集）

13.1 UNION / UNION ALL

SELECT employee_id, job_id
FROM   employees
UNION
SELECT employee_id, job_id
FROM   job_history;
  • UNION ALL 操作符返回两个查询的结果集的并集。对于两个结果集的重复部分，不去重。
  • UNION ALL 操作符返回两个查询的结果集的并集。对于两个结果集的重复部分，去重。
  • 其中查询字段个数、数据类型要相同。
  • 如果查询字段起别名，以上一个select语句的别名为准。
  • 默认排序为第一个select 语句 的employee_id 升序排列。

13.2 INTERSECT

SELECT employee_id, job_id
FROM   employees
INTERSECT
SELECT employee_id, job_id
FROM   job_history;
  • INTERSECT 操作符返回两个结果集的交集

13.3 MINUS

SELECT employee_id,job_id
FROM   employees
MINUS
SELECT employee_id,job_id
FROM   job_history;

MINUS操作符：返回两个结果集的差集

13.4 使用相对位置排序举例

SELECT 'sing' AS "My dream", 3 
FROM dual
UNION
SELECT 'I`d like to teach', 1
FROM dual
UNION 
SELECT 'the world to', 2
FROM dual
ORDER BY 2;

列名显示第一个查询的别名，由于加了order by ,结果以第2列升序排列。

COLUMN a_dummy NOPRINT

UNION
SELECT 'I`d like to teach', 1
FROM dual
UNION

打印结果：

13.5 使用 SET 操作符注意事项

  • 在SELECT 列表中的列名和表达式在数量和数据类型上要相对应

  • 括号可以改变执行的顺序

  • ORDER BY 子句:

    只能在语句的最后出现

    可以使用第一个查询中的列名, 别名或相对位置

  • 除 UNION ALL之外，系统会自动将重复的记录删除 系统将第一个查询的列名显示在输出中 除 UNION ALL之外，系统自动按照第一个查询中的第一个列的升序排列

14、高级子查询

14.1 多列子查询

  • 主查询与子查询返回的多个列进行比较

示例：查询与141号或174号员工的manager_id和department_id相同的其他员工的employee_id, manager_id, department_id

SELECT	employee_id, manager_id, department_id
FROM	employees
WHERE  (manager_id, department_id) IN
                      (SELECT manager_id, department_id
                       FROM   employees
                       WHERE  employee_id IN (141,174))
AND	employee_id NOT IN (141,174);

14.2 在 FROM 子句中使用子查询

示例：返回比本部门平均工资高的员工的last_name, department_id, salary及平均工资

SELECT  a.last_name, a.salary, 
        a.department_id, b.salavg
FROM    employees a, (SELECT   department_id, 
                      AVG(salary) salavg
                      FROM     employees
                      GROUP BY department_id) b
WHERE   a.department_id = b.department_id
AND     a.salary > b.salavg;

14.3 单列子查询

示例：显示员工的employee_id,last_name和location。其中，若员工department_id与location_id为1800的department_id相同，则location为’Canada’,其余则为’USA’。

SELECT employee_id, last_name,
       (CASE
        WHEN department_id =
                
                 
        THEN 'Canada' ELSE 'USA' END) location
FROM   employees;

14.4 EXISTS/NOT EXISTS 操作符

示例：查询公司管理者的employee_id,last_name,job_id,department_id信息

SELECT employee_id, last_name, job_id, department_id
FROM   employees outer
WHERE  EXISTS ( SELECT 'X'
                 FROM   employees
                 WHERE  manager_id = 
                        outer.employee_id);

示例：查询departments表中，不存在于employees表中的部门的department_id和department_name

SELECT department_id, department_name
FROM departments d
WHERE NOT EXISTS (SELECT 'X'
                  FROM   employees
                  WHERE  department_id 
                         = d.department_id);

14.5 WITH 子句

  • 使用 WITH 子句, 可以避免在 SELECT 语句中重复书写相同的语句块
  • WITH 子句将该子句中的语句块执行一次并存储到用户的临时表空间中
  • 使用 WITH 子句可以提高查询效率

eg:查询公司中各部门的总工资大于公司中各部门的平均总工资的部门信息

--定义子句
WITH dept_costs  AS (
   SELECT  d.department_name, SUM(e.salary) AS dept_total
   FROM    employees e, departments d
   WHERE   e.department_id = d.department_id
   GROUP BY d.department_name),
avg_cost    AS (
   SELECT SUM(dept_total)/COUNT(*) AS dept_avg
   FROM   dept_costs)


--使用子句
SELECT * 
FROM   dept_costs 
WHERE  dept_total >
        (SELECT dept_avg 
         FROM avg_cost)
ORDER BY department_name;
