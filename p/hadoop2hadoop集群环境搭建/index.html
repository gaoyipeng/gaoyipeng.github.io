一、环境介绍

  • centos7.5
  • jdk-8u212-linux-x64.tar.gz
  • vmware15.5
  • hadoop-3.1.3

二、基础环境配置

先搭建一台模板机,后续通过克隆来创建其他虚拟机(同步创建root用户和普通用户admin)。模板机IP：

192.168.40.128 

vim  /etc/hostname
##修改机器名称
hadoop0

2.1 模板机操作

1、配置admin用户具有 root 权限，方便后期加 sudo 执行 root 权限的命令

vim /etc/sudoers
##修改/etc/sudoers 文件，在%wheel 这行下面添加一行
admin   ALL=(ALL) NOPASSWD:ALL

2、在/opt目录下创建文件夹，并修改所属主和所属组

mkdir /opt/module
mkdir /opt/software

chown admin:admin /opt/module
chown admin:admin /opt/software

3、卸载虚拟机自带JDK

rpm -qa | grep -i java | xargs -n1 rpm -e --nodeps

2.2 克隆3台虚拟机

关闭模板机，克隆3台虚拟，IP分别是：

192.168.40.129 
192.168.40.130 
192.168.40.131

并修改对应的hostname分别为hadoop1、hadoop2、hadoop3，同时修改4台虚拟机的hosts文件：

vim /etc/hosts

##插入以下内容
192.168.40.128 hadoop0
192.168.40.129 hadoop1
192.168.40.130 hadoop2
192.168.40.131 hadoop3

注意，此处要配置内网IP（通过ifconfig命令查看）。

然后重启虚拟机。

2.3 安装JDK

分别在hadoop1、hadoop2、hadoop33台虚拟机上安装JDK。上传jdk安装包到/opt/software目录下。

##解压java到/opt/module下
[admin@hadoop1 software]$ tar -zxvf jdk-8u212-linux-x64.tar.gz -C ../module/

在 /etc/profile.d/目录下新建myjdk.sh（注意需要使用root账户）

cd /etc/profile.d/
vim myjdk.sh

export JAVA_HOME=/opt/module/jdk1.8.0_212
export CLASSPATH=.:${JAVA_HOME}/jre/lib/rt.jar:${JAVA_HOME}/lib/dt.jar:${JAVA_HOME}/lib/tools.jar
export PATH=$PATH:${JAVA_HOME}/bin

执行以下命令，使PATH生效：

source /etc/profile

查看JDK是否安装成功

[root@hadoop1 profile.d]# java -version
java version "1.8.0_212"
Java(TM) SE Runtime Environment (build 1.8.0_212-b10)
Java HotSpot(TM) 64-Bit Server VM (build 25.212-b10, mixed mode)

2.4 安装hadoop

Hadoop 官方网站：http://hadoop.apache.org/

Hadoop 下载地址：https://archive.apache.org/dist/hadoop/common/hadoop-3.1.3/

hadoop的安装和jdk是类似的。上传jdk安装包到/opt/software目录下。

##解压hadoop /opt/module下
[admin@hadoop3 software]# tar -zxvf hadoop-3.1.3.tar.gz -C ../module/

在 /etc/profile.d/目录下新建myhadoop.sh（注意需要使用root账户）

cd /etc/profile.d/
vim myhadoop.sh

export HADOOP_HOME=/opt/module/hadoop-3.1.3
export PATH=$PATH:$HADOOP_HOME/bin
export PATH=$PATH:$HADOOP_HOME/sbin

执行以下命令，使PATH生效：

source /etc/profile

查看hadoop是否安装成功

hadoop version

三、xsync分发脚本工具

后期会涉及很多集群间的文件同步，为了可以快速在集群建进行文件拷贝，我们创建一个xsync分发工具,实现循环复制文件到所有节点的相同目录下。

原理是使用rsync命令：

rsync -av $pdir/$fname $user@$host:$pdir/$fname

命令 选项参数 要拷贝的文件路径/名称 目的地用户@主机:目的地路径/名称

选项参数说明
-a 归档拷贝
-v 显示复制过程

3.1 创建自定义命令xsync

我们在hadoop1机器的/bin目录下新建xsync文件（在/bin目录是因为该目录属于$PATH,root和普通用户都可以执行该目录下的命令），输入以下内容：

#!/bin/bash
#1. 判断参数个数
if [ $# -lt 1 ]
then
 echo Not Enough Arguement!
 exit;
fi
#2. 遍历集群所有机器
for host in hadoop1 hadoop2 hadoop3
do
 echo ==================== $host ====================
 #3. 遍历所有目录，挨个发送
 for file in $@
 do
 #4. 判断文件是否存在
 if [ -e $file ]
 then
 #5. 获取父目录
 pdir=$(cd -P $(dirname $file); pwd)
 #6. 获取当前文件的名称
 fname=$(basename $file)
 ssh $host "mkdir -p $pdir"
 rsync -av $pdir/$fname $host:$pdir
 else
 echo $file does not exists!
 fi
 done
done

修改文件执行权限

chmod 755 xsync

我们在/opt目录下新建测试文件，进行验证。

可以看到文件已经被批量同步到集群的其它机器上了。

3.2 设置xsync集群免密传输

但是我们在使用xsync命令时，还需要依次输入各集群机器的密码，比较麻烦，我们下面配置一下免密传输。

我们在hadoop1中，执行ssh-keygen -t rsa，然后敲（三个回车），就会生成两个文件 id_rsa（私钥）、id_rsa.pub（公钥）

将公钥拷贝到要免密登录的目标机器上。

ssh-copy-id hadoop1
ssh-copy-id hadoop2
ssh-copy-id hadoop3

我们再次验证同步文件，可以看到无需密码了：

注意，这部分演示我们是用root账户操作的，我们需要在所有集群节点，分别使用root和admin用户，重复这部分操作，实现集群建任意节点免密传输。

四、Hadoop运行模式

Hadoop 运行模式包括：本地模式、伪分布式模式以及完全分布式模式。

➢ 本地模式：单机运行，数据存储在Linux本地。

➢ 伪分布式模式：也是单机运行，但是具备 Hadoop 集群的所有功能，一台服务器模拟一个分布式的环境。数据存储在HDFS。

➢ 完全分布式模式：多台服务器组成分布式环境。生产环境使用。

我们主要学习分布式模式。

5.1 集群部署规划

➢ ResourceManager 也很消耗内存，不要和 NameNode、SecondaryNameNode 配置在同一台机器上。

5.2 配置文件说明

Hadoop 配置文件分两类：默认配置文件和自定义配置文件，只有用户想修改某一默认配置值时，才需要修改自定义配置文件，更改相应属性值。

5.2.1默认配置文件（default.xml）：

默认配置文件 位置
core-default.xml /hadoop-3.1.3/share/hadoop/common/hadoop-common-3.1.3.jar/core-default.xml
hdfs-default.xml /hadoop-3.1.3/share/hadoop/hdfs/hadoop-hdfs-3.1.3.jar/hdfs-default.xml
yarn-default.xml /hadoop-3.1.3/share/hadoop/yarn/hadoop-yarn-common-3.1.3.jar/yarn-default.xml
mapred-default.xml /hadoop-3.1.3/share/hadoop/mapreduce//hadoop-3.1.3/share/hadoop/mapreduce

5.2.2自定义配置文件（site.xml）

core-site.xml、hdfs-site.xml、yarn-site.xml、mapred-site.xml 四个配置文件存放在$HADOOP_HOME/etc/hadoop 这个路径上，用户可以根据项目需求重新进行修改配置。

5.2 配置集群

5.2.1 配置 core-site.xml

<!-- 指定 NameNode 的地址及端口 -->
 <property>
 	<name>fs.defaultFS</name>
 	<value>hdfs://hadoop1:8020</value>
 </property>
 <!-- 指定 hadoop 数据的存储目录 -->
 <property>
 	<name>hadoop.tmp.dir</name>
 	<value>/opt/module/hadoop-3.1.3/data</value>
 </property>
 <!-- 配置 HDFS 网页登录使用的静态用户为 admin -->
 <property>
	<name>hadoop.http.staticuser.user</name>
 	<value>admin</value>
 </property>

5.2.2 配置 hdfs-site.xml

<!-- NameNode web 端访问地址-->
<property>
 	<name>dfs.namenode.http-address</name>
 	<value>hadoop1:9870</value>
 </property>
<!-- SecondaryNameNode web 端访问地址-->
 <property>
 	<name>dfs.namenode.secondary.http-address</name>
 	<value>hadoop3:9868</value>
 </property>

5.2.3 配置 yarn-site.xml

<!-- 指定 MapReduce 走 shuffle -->
 <property>
 	<name>yarn.nodemanager.aux-services</name>
 	<value>mapreduce_shuffle</value>
 </property>
 <!-- 指定 ResourceManager 的地址-->
 <property>
 	<name>yarn.resourcemanager.hostname</name>
 	<value>hadoop2</value>
 </property>
 <!-- 环境变量的继承 -->
 <property>
 	<name>yarn.nodemanager.env-whitelist</name>
    <value>JAVA_HOME,HADOOP_COMMON_HOME,HADOOP_HDFS_HOME,HADOOP_CO
    NF_DIR,CLASSPATH_PREPEND_DISTCACHE,HADOOP_YARN_HOME,HADOOP_MAPRED_HOME</value>
 </property>

5.2.4 配置 mapred-site.xml

<!-- 指定 MapReduce 程序运行在 Yarn 上 -->
 <property>
 	<name>mapreduce.framework.name</name>
 	<value>yarn</value>
 </property>

<property>
  <name>yarn.app.mapreduce.am.env</name>
  <value>HADOOP_MAPRED_HOME=/opt/module/hadoop-3.1.3</value>
</property>
<property>
  <name>mapreduce.map.env</name>

七、配置历史服务器

我们发现当yarn控制界面刷新后，再次点击history,发现无法查看历史，或者重启yarn后，计算记录会丢失，所以此处我们需要配置历史服务器。

我们首先在hadoop2关闭yarn：

[admin@hadoop2 sbin]$ ./stop-yarn.sh

然后在需要mapred-site.xml中添加如下配置：

<!-- 历史服务器端地址：hadoop内部使用 -->
<property>
 <name>mapreduce.jobhistory.address</name>
 <value>hadoop1:10020</value>
</property>
<!-- 历史服务器 web 端地址 -->
<property>
 <name>mapreduce.jobhistory.webapp.address</name>
 <value>hadoop1:19888</value>
</property>

同步该文件至集群其他节点

[admin@hadoop1 hadoop]$ xsync mapred-site.xml

注意：历史服务器需要手动启动，不会随着yarn启动，我们先在Hadoop2重启yarn,然后在hadoop1上启动历史服务器：

mapred --daemon start historyserver

然后我们再次进行计算：

[admin@hadoop1 hadoop]$ hadoop jar /opt/module/hadoop-3.1.3/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.1.3.jar  wordcount /input /output1

注意：这里是/output1，第一次计算是/output。

这次也是试了2次才成功，低配破笔记本误我~~，我们再次查看history，显示正常：

除此之外，我们重启yarn，访问http://192.168.40.130:8088/cluster/apps，可以看到计算历史记录为空

此时我们访问http://hadoop1:19888/jobhistory，就可以看到历史记录了

八、配置日志保存功能

我们前面已经配置了历史服务器，我们如果想要看本次任务的具体执行日志，可以点击对应的job ID

但是现在由于执行日志过程未被保存，点击后无法查看日志，所以我们需要配置日志保存功能。

日志保存概念：应用运行完成以后，将程序运行日志信息上传到 HDFS 系统上。

注意：开启日志聚集功能，需要重新启动 NodeManager 、ResourceManager 和HistoryServer。

我们先关闭yarn、HistoryServer服务

[admin@hadoop1 hadoop]$ mapred --daemon stop historyserver

[admin@hadoop2 sbin]$ ./stop-yarn.sh

修改yarn-site.xml,添加如下信息

[admin@hadoop1 hadoop]$ vim yarn-site.xml

<!-- 开启日志聚集功能 -->
<property>
 <name>yarn.log-aggregation-enable</name>
 <value>true</value>
</property>
<!-- 设置日志聚集服务器地址 -->
<property> 
 <name>yarn.log.server.url</name> 
 <value>http://hadoop1:19888/jobhistory/logs</value>
</property>
<!-- 设置日志保留时间为 7 天 -->
<property>
 <name>yarn.log-aggregation.retain-seconds</name>
 <value>604800</value>
</property>

同步分发到其他机器节点。

[admin@hadoop1 hadoop]$ xsync yarn-site.xml

然后重启yarn、HistoryServer服务

[admin@hadoop2 sbin]$ ./start-yarn.sh

[admin@hadoop1 hadoop]$ mapred --daemon start historyserver

然后我们再次进行计算：

[admin@hadoop1 hadoop]$ hadoop jar /opt/module/hadoop-3.1.3/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.1.3.jar  wordcount /input /output2

我们查看本次计算的日志：
