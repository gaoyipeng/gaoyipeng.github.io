一、Hadoop 高可用集群

1.1 Hadoop 高可用集群规划

我们先来看下目前我们的Hadoop 集群的现状。

hadoop1 hadoop2 hadoop3 hadoop4 hadoop5
HDFS NameNode DataNode SecondaryNameNode DataNode DataNode
DataNode DataNode
YARN NodeManager ResourceManager NodeManager NodeManager NodeManager
NodeManager

可以看到我们的NameNode和ResourceManager都只有一个节点，如果节点发生故障，就会导致集群不可用。此时我们就需要HA高可用集群了（包括 HDFS 的 HA 和 YARN 的 HA），HA集群规划如下：

hadoop1 hadoop2 hadoop3 hadoop4 hadoop5
HDFS NameNode NameNode NameNode DataNode DataNode
DataNode DataNode DataNode
journalnode journalnode journalnode
YARN ResourceManager ResourceManager ResourceManager NodeManager NodeManager
NodeManager NodeManager NodeManager
Zookeeper Zookeeper Zookeeper Zookeeper
ZKFC ZKFC ZKFC

注意：前提是服务器直接可以使用ssh免密登录

1.2 HA 需要考虑的问题

1）HDFS如何实现HA

HDFS HA 功能通过配置多个 NameNodes(Active/Standby)实现在集群中对 NameNode 的热备来解决上述问题。如果出现故障，如机器崩溃或机器需要升级维护，这时可通过 Zookeeper 的临时节点将 NameNode 很快的切换到另外一台机器。

Active/Standby：活动/待机

2）怎么保证三台 namenode 的数据一致

（1）Fsimage:让一台 namenode（Active）生成数据,让其他机器 NameNodes（Standby） 同步
（2）Edits:需要引进新的模块 JournalNode 来保证 edtis 的文件的数据一致性

3）在现有架构中，SecondaryNameNode定期合并fsimage和edtis，HA架构中如何处理。

由 standby（待机）的 namenode节点来处理。

4）如果当前Active状态的ResourceManager或者NameNodes挂了，其他备用节点怎么变为Active状态。

自动故障转移部署增加了两个新组件：ZooKeeper 和 ZKFailoverController（ZKFC），利用了 Zookeeper 的临时节点。

5）当前 ResourceManager（Active）如果发生故障，上面有很多的计算程序在等待运行,其他的ResourceManager怎么将这些程序接手过来接着跑。

ResourceManager会将当前的所有计算程序的状态存储在 Zookeeper 中,其他 ResourceManager 上位后会去读取，然后接着跑。

二、Zookeeper集群搭建

我们搭建Hadoop 高可用集群依赖Zookeeper，所以我们先在hadoop1、hadoop2、hadoop3节点搭建Zookeeper集群。

下载:https://zookeeper.apache.org/releases.html#download

最新稳定版：

注意：下载带-bin的版本

1、上传到hadoop1、hadoop2、hadoop3节点并解压：

[admin@hadoop1 software]$ tar -zxvf apache-zookeeper-3.8.2-bin.tar.gz -C /opt/module/

2、在/opt/module/apache-zookeeper-3.8.2-bin/目录下新建 zkData文件夹

mkdir zkData

3、在/opt/module/apache-zookeeper-3.8.2-bin/zkData目录下新建myid文件

vim myid

分别在hadoop1、hadoop2、hadoop3机器的myid文件中输入编号：1、2、3

4、重命名/opt/module/apache-zookeeper-3.8.2-bin/conf 这个目录下的 zoo_sample.cfg 为 zoo.cfg，并修改如下内容：

dataDir=/opt/module/apache-zookeeper-3.8.2-bin/zkData
server.1=hadoop1:2888:3888
server.2=hadoop2:2888:3888
server.3=hadoop3:2888:3888

配置参数解读：server.A=B:C:D。

A 是一个数字，表示这个是第几号服务器；集群模式下配置一个文件 myid，这个文件在 dataDir 目录下，这个文件里面有一个数据就是 A 的值，Zookeeper 启动时读取此文件，拿到里面的数据与 zoo.cfg 里面的配置信息比较从而判断到底是哪个 server。
B 是这个服务器的地址；
C 是这个服务器 Follower 与集群中的 Leader 服务器交换信息的端口；
D 是万一集群中的 Leader 服务器挂了，需要一个端口来重新进行选举，选出一个新的Leader，而这个端口就是用来执行选举时服务器相互通信的端口。

5、编写启动脚本

我们切换root用户，在/bin目录下新建zk文件：

vim zk

#!/bin/bash
case $1 in
"start"){
for i in hadoop1 hadoop2 hadoop3
do
 echo ---------- zookeeper $i 启动 ------------
ssh $i "/opt/module/apache-zookeeper-3.8.2-bin/bin/zkServer.sh start"
done
};;
"stop"){
for i in hadoop1 hadoop2 hadoop3
do
 echo ---------- zookeeper $i 停止 ------------
ssh $i "/opt/module/apache-zookeeper-3.8.2-bin/bin/zkServer.sh stop"
done
};;
"status"){
for i in hadoop1 hadoop2 hadoop3
do
 echo ---------- zookeeper $i 状态 ------------
ssh $i "/opt/module/apache-zookeeper-3.8.2-bin/bin/zkServer.sh status"
done
};;
esac

修改文件执行权限

[root@hadoop1 bin]# chmod 755 zk

三、配置HDFS-HA

3.1 修改配置文件

修改core-site.xml

<configuration> 
    <!-- 把多个 NameNode 的地址组装成一个集群 mycluster -->  
    <property> 
        <name>fs.defaultFS</name>  
        <value>hdfs://mycluster</value> 
    </property>  
    <!-- 指定 hadoop 运行时产生文件的存储目录 -->  
    <property> 
        <name>hadoop.tmp.dir</name>  
        <value>/opt/module/hadoop-3.1.3/data</value> 
    </property>  
    <!-- 配置 HDFS 网页登录使用的静态用户为 admin -->  
    <property> 
        <name>hadoop.http.staticuser.user</name>  
        <value>admin</value> 
    </property>  
    <!--配置垃圾回收时间为 30 分钟-->  
    <property> 
        <name>fs.trash.interval</name>  
        <value>30</value> 
    </property>  
    <!-- 指定 zkfc 要连接的 zkServer 地址 -->  
    <property> 
        <name>ha.zookeeper.quorum</name>  
        <value>hadoop1:2181,hadoop2:2181,hadoop3:2181</value> 
    </property>  
    <!-- NN 连接 JN 重试次数，默认是 10 次 -->  
    <property> 
        <name>ipc.client.connect.max.retries</name>  
        <value>20</value> 
    </property>  
    <!-- 重试时间间隔，默认 1s -->  
    <property> 
        <name>ipc.client.connect.retry.interval</name>  
        <value>5000</value> 
    </property> 
</configuration>

3.5 HA自动切换失败说明

我在测试时发现，手动杀掉进程后，HA 自动切换不成功，排查发现是未安装psmisc导致的。在集群节点执行以下命令即可。

[admin@hadoop1 hadoop-3.1.3] sudo yum -y install psmisc

再次执行上面的集群操作，就可以实现HDFS-HA。

        <value>JAVA_HOME,HADOOP_COMMON_HOME,HADOOP_HDFS_HOME,HADOOP_CONF_DIR,CLAS SPATH_PREPEND_DISTCACHE,HADOOP_YARN_HOME,HADOOP_MAPRED_HOME</value> 
    </property> 
    
    
    <!-- 历史服务器端地址：hadoop内部使用 -->
    <property>
     <name>mapreduce.jobhistory.address</name>
     <value>hadoop1:10020</value>
    </property>
    <!-- 历史服务器 web 端地址 -->
    <property>
     <name>mapreduce.jobhistory.webapp.address</name>
     <value>hadoop1:19888</value>
    </property>
    <!-- 开启日志聚集功能 -->
    <property>
     <name>yarn.log-aggregation-enable</name>
     <value>true</value>
    </property>
    <!-- 设置日志聚集服务器地址 -->
    <property> 
     <name>yarn.log.server.url</name> 
     <value>http://hadoop1:19888/jobhistory/logs</value>
    </property>
    <!-- 设置日志保留时间为 7 天 -->
    <property>
     <name>yarn.log-aggregation.retain-seconds</name>
     <value>604800</value>
    </property>
</configuration>

然后分发文件。

[admin@hadoop2 hadoop-3.1.3]$  hdfs --daemon start datanode

六、Hadoop集群登录时间太久无法正常关闭

在集群长时间启动后，有此我使用myhadoop stop命令关闭集群，发现失效，进程一直存在。

问题原因：

Hadoop启动后，会把进程的PID号存储在一个目录下（默认为：/tmp），这样脚本就可以按照进程PID去关闭进程了。但是/tmp是临时目录，系统会定时清理该目录中的文件。显然把pid文件放在这里是不靠谱的，pid文件长时间不被访问，就被清理了。

解决方案：

先使用kill -9 的方式杀死进程。需要在配置文件中更改默认的pid存放位置即可。修改etc/hadoop/hadoop-env.sh，添加以下配置

export HADOOP_PID_DIR=/opt/module/hadoop-3.1.3/pid

分发配置，重启集群即可。
