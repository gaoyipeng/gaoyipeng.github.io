Hadoop-ReduceTask ReduceTask过程分析、OutputFormat介绍

Aug 18, 2023
阅读时长: 3 分钟

一、MapReduce工作流程

ReduceTask：负责 Reduce 阶段的整个数据处理流程。

二 ReduceTask过程分析

  • （1）Copy 阶段：ReduceTask 从各个 MapTask 上远程拷贝一片数据，并针对某一片数据，如果其大小超过一定阈值，则写到磁盘上，否则直接放到内存中。
  • （2）Sort 阶段：在远程拷贝数据的同时，ReduceTask 启动了两个后台线程对内存和磁盘上的文件进行合并，以防止内存使用过多或磁盘上文件过多。按照 MapReduce 语义，用户编写 reduce()函数输入数据是按 key 进行聚集的一组数据。为了将 key 相同的数据聚在一起，Hadoop 采用了基于排序的策略。由于各个 MapTask 已经实现对自己的处理结果进行了局部排序，因此，ReduceTask 只需对所有数据进行一次归并排序即可。
  • （3）Reduce 阶段：reduce()函数将计算结果写到 HDFS 上。

2.1 OutputFormat 数据输出

OutputFormat是MapReduce输出的基类，所有实现MapReduce输出都实现了 OutputFormat接口。

默认输出格式为TextOutputFormat：按行输出到文件中。

2.3 自定义 OutputFormat实例

需求：在《Hadoop-MapReduce介绍及使用示例》示例代码的基础上，新增需求如下：将统计结果按照手机不同开头号码的输出到不同文件中。

分区规则：
136 开头手机号   文件1：txt136.log
137 开头手机号	文件2：txt137.log
138 开头手机号	文件3：txt138.log
139 开头手机号	文件4：txt139.log
其他  文件5：txtother.log

之前我们已经使用Partition实现过分区，我们本次使用OutputFormat来实现该需求。

2.3.1 编写 自定义RecordWriter 类

package com.sxdx.hdfs.mapreduce.output;

import org.apache.hadoop.fs.FSDataOutputStream;
import org.apache.hadoop.fs.FileSystem;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IOUtils;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.RecordWriter;
import org.apache.hadoop.mapreduce.TaskAttemptContext;

import java.io.IOException;

public class PhoneRecordWriter extends RecordWriter<Text, FlowBean> {

    private FSDataOutputStream txt136;
    private FSDataOutputStream txt137;
    private FSDataOutputStream txt138;
    private FSDataOutputStream txt139;
    private FSDataOutputStream txtother;

    public PhoneRecordWriter(TaskAttemptContext job) {
        try {
            //获取文件系统对象
            FileSystem fs = FileSystem.get(job.getConfiguration());
            //用文件系统对象创建两个输出流对应不同的目录
            txt136 = fs.create(new Path("d:/flowoutput/txt136.log"));
            txt137 = fs.create(new Path("d:/flowoutput/txt137.log"));
            txt138 = fs.create(new Path("d:/flowoutput/txt138.log"));
            txt139 = fs.create(new Path("d:/flowoutput/txt139.log"));
            txtother = fs.create(new Path("d:/flowoutput/txtother.log"));
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    /**
     * Writes a key/value pair.
     *
     * @param key   the key to write.
     * @param value the value to write.
     * @throws IOException
     */
    @Override
    public void write(Text key, FlowBean value) throws IOException, InterruptedException {
        String phone = key.toString();
        //根据一行的 log 数据是否包含 atguigu,判断两条输出流输出的内容
        if (phone.startsWith("136")) {
            txt136.writeBytes(phone + "\t" + value.toString() +"\n");
        } else if (phone.startsWith("137")){
            txt137.writeBytes(phone + "\t" + value.toString() +"\n");
        }else if (phone.startsWith("138")){
            txt138.writeBytes(phone  + "\t"+ value.toString() +"\n");
        }else if (phone.startsWith("139")){
            txt139.writeBytes(phone + "\t"+ value.toString() +"\n");
        }else {
            txtother.writeBytes(phone + "\t" + value.toString() +"\n");
        }
    }

    /**
     * Close this <code>RecordWriter</code> to future operations.
     *
     * @param context the context of the task
     * @throws IOException
     */
    @Override
    public void close(TaskAttemptContext context) throws IOException, InterruptedException {
        //关流
        IOUtils.closeStream(txt136);
        IOUtils.closeStream(txt137);
        IOUtils.closeStream(txt138);
        IOUtils.closeStream(txt139);
        IOUtils.closeStream(txtother);
    }
}

2.3.3 Drivers设置自定义 OutputFormat方法

package com.sxdx.hdfs.mapreduce.output;

import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;

import java.io.IOException;

public class FlowDriver {
    public static void main(String[] args) throws IOException, ClassNotFoundException, InterruptedException {
        //1 获取 job 对象
        Configuration conf = new Configuration();
        Job job = Job.getInstance(conf);
        //2 关联本 Driver 类
        job.setJarByClass(FlowDriver.class);
        //3 关联 Mapper 和 Reducer
        job.setMapperClass(FlowMapper.class);
        job.setReducerClass(FlowReducer.class);

        //4 设置 Map 端输出 KV 类型
        job.setMapOutputKeyClass(Text.class);
        job.setMapOutputValueClass(FlowBean.class);

        //5 设置程序最终输出的 KV 类型
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(FlowBean.class);

        //6 设置程序的输入输出路径 new Path(args[0]) new Path(args[1]) 用于接收命令参数
        FileInputFormat.setInputPaths(job, new Path("D:\\inputflow"));
        //而 fileoutputformat 要输出一个_SUCCESS 文件，所以在这还得指定一个输出目录
        FileOutputFormat.setOutputPath(job, new Path("D:\\flowoutput\\PhoneOutputFormat"));

        //设置自定义的 outputformat
        job.setOutputFormatClass(PhoneOutputFormat.class);

        //7 提交 Job
        boolean b = job.waitForCompletion(true);
        System.exit(b ? 0 : 1);
    }
}

2.4 ReduceTask 并行度

MapTask 并行度由切片个数决定，切片个数由输入文件和切片规则决定。那么ReduceTask并行度由谁决定？

ReduceTask 的并行度同样影响整个 Job 的执行并发度和执行效率，但与 MapTask 的并发数由切片数决定不同，ReduceTask 数量的决定是可以直接手动设置：

// 默认值是 1，手动设置为 5
job.setNumReduceTasks(5);
  • （1）ReduceTask=0，表示没有Reduce阶段，输出文件个数和Map个数一致。
  • （2）ReduceTask默认值就是1，所以输出文件个数为一个。
  • （3）如果数据分布不均匀，就有可能在Reduce阶段产生数据倾斜
  • （4）ReduceTask数量并不是任意设置，还要考虑业务逻辑需求，有些情况下，需要计算全局汇总结果，就只能有1个ReduceTask。
  • （5）具体多少个ReduceTask，需要根据集群性能而定。需要实验设置。
  • （6）如果分区数不是1，但是ReduceTask为1，是否执行分区过程。我们在上一节介绍分区时已经介绍过。答案是：不执行分区过程。因为在MapTask的源码中，执行分区的前提是先判断ReduceNum个数是否大于1。不大于1肯定不执行。
