Hadoop-Yarn 公平调度器

Aug 29, 2023
阅读时长: 2 分钟

环境说明：原虚拟机配置太差，我们新搭建了集群，还是3台，配置为 8c 16g 300g，所以后续配置是在这个硬件配置的基础上进行的。

192.168.2.169  hadoop1
192.168.2.170  hadoop2
192.168.2.171  hadoop3

一、公平调度器配置

1.1参考文件

（1）配置文件参考资料：

https://hadoop.apache.org/docs/r3.1.3/hadoop-yarn/hadoop-yarn-site/FairScheduler.html

（2）任务队列放置规则参考资料：

https://blog.cloudera.com/untangling-apache-hadoop-yarn-part-4-fair-scheduler-queue-basics/

1.2 需求

公平调度器默认有一个队列default,我们再创建2个队列，分别是 hive 和 admin（以用户所属组命名）。期望实现以下效果：若用户提交任务时指定队列，则任务提交到指定队列运行；若未指定队列，hive 用户提交的任务到 root.group.hive 队列运行，admin提交的任务到 root.group.admin队列运行（注：group 为用户所属组）。

公平调度器的配置涉及到两个文件，一个是 yarn-site.xml，另一个是公平调度器队列分配文件 fair-scheduler.xml（文件名在yarn-site.xml文件中自定义）。

二、配置多队列的公平调度器

2.1 创建用户

[root@hadoop1 ~]# useradd hive
[root@hadoop1 ~]# passwd hive

admin已经存在，不需要创建。

2.2 修改 yarn-site.xml 文件

首先我们备份修改 yarn-site.xml 文件（避免后续想要换回容量调度器时还得修改文件）。

[admin@hadoop1 hadoop]$ cp yarn-site.xml yarn-site.xml.Capacity

然后修改 yarn-site.xml 文件：

<property>
	<description>配置使用公平调度器</description>
 	<name>yarn.resourcemanager.scheduler.class</name>
	<value>org.apache.hadoop.yarn.server.resourcemanager.scheduler.fair.FairScheduler</value>
</property>

<property>
	 <description>指定公平调度器队列分配配置文件</description>
     <name>yarn.scheduler.fair.allocation.file</name>
     <value>/opt/module/hadoop-3.1.3/etc/hadoop/fair-scheduler.xml</value>
</property>

<!--如果为false，队列间不会进行空闲资源共享-->
<property>
     <name>yarn.scheduler.fair.preemption</name>
     <value>true</value>
     <description>允许队列间资源抢占</description>
</property>

2.3 新建 fair-scheduler.xml配置文件

<?xml version="1.0"?>
<allocations>
 <!-- 单个队列中 Application Master 占用资源的最大比例,取值 0-1 ，企业一般配置 0.1 -->
 <queueMaxAMShareDefault>0.5</queueMaxAMShareDefault>
 <!-- 单个队列最大资源的默认值  -->
 <queueMaxResourcesDefault>8192mb,8vcores</queueMaxResourcesDefault>
    
 <!-- 增加一个队列 hive -->
 <queue name="hive">
     <!-- 队列最小资源 -->
     <minResources>2048mb,2vcores</minResources>
     <!-- 队列最大资源 -->
     <maxResources>4096mb,4vcores</maxResources>
     <!-- 队列中最多同时运行的应用数，默认 50，根据线程数配置 -->
     <maxRunningApps>4</maxRunningApps>
     <!-- 队列中 Application Master 占用资源的最大比例 -->
     <maxAMShare>0.5</maxAMShare>
     <!-- 该队列资源权重,默认值为 1.0 -->
      <weight>1.0</weight>
     <!-- 队列内部的资源分配策略 -->
     <schedulingPolicy>fair</schedulingPolicy>
 </queue>
    
 <!-- 增加一个队列 admin -->
 <queue name="admin" type="parent">
     <!-- 队列最小资源 -->
     <minResources>2048mb,2vcores</minResources>
     <!-- 队列最大资源 -->
     <maxResources>4096mb,4vcores</maxResources>
     <!-- 队列中最多同时运行的应用数，默认 50，根据线程数配置 -->
     <maxRunningApps>4</maxRunningApps>
     <!-- 队列中 Application Master 占用资源的最大比例 -->
     <maxAMShare>0.5</maxAMShare>
     <!-- 该队列资源权重,默认值为 1.0 -->
     <weight>1.0</weight>
     <!-- 队列内部的资源分配策略 -->
     <schedulingPolicy>fair</schedulingPolicy>
 </queue>
    
 <!-- 任务队列分配策略,可配置多层规则,从第一个规则开始匹配,直到匹配成功 -->
 <queuePlacementPolicy>
     <!-- 提交任务时指定队列,如未指定提交队列,则继续匹配下一个规则; 
		false 表示：如果指定队列不存在,不允许自动创建-->
     <rule name="specified" create="false"/>
     <!--nestedUserQueue只针对type="parent"的队列。
 		提交到root.group.username队列,若root.group不存在,不允许自动创建；
		若root.group.user 不存在,允许自动创建-->
     <rule name="nestedUserQueue" create="true">
        <rule name="primaryGroup" create="false"/>
     </rule>
     <!-- 最后一个规则必须为 reject 或者 default。
	Reject 表示拒绝创建提交失败，default 表示把任务提交到 default 队列 -->
     <rule name="default" />
 </queuePlacementPolicy>
</allocations>

注意：要注意各参数配置合理，我在测试时由于maxAMShare设置太小，导致任务执行一半就卡死。

同步文件后重启服务，可以看到3个队列，队列长度也和队列内存配置匹配：

尝试以下计算命令：

1、指定队列

[admin@hadoop1 hadoop]$ hadoop jar /opt/module/hadoop-3.1.3/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.1.3.jar pi -D mapreduce.job.queuename=root.hive 5 100000

2、使用admin账户执行，但不指定队列

[admin@hadoop1 hadoop]$ hadoop jar /opt/module/hadoop-3.1.3/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.1.3.jar pi   5 100000

3、使用hive

[hive@hadoop1 ~]$ hadoop jar /opt/module/hadoop-3.1.3/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.1.3.jar pi  5 100000

但是报错了

执行如下命令：

hadoop dfs -mkdir -p /tmp（如果路径存在可不执行）
hadoop dfs -chown hive:hive /tmp（如果所属用户一致可不执行）或者 hadoop fs -chmod -R 777 /tmp

再次执行计算任务，可以看到该任务是default队列,这是由于nestedUserQueue只针对type=“parent"的队列，而hive不是type=“parent”，并且该命令未指定明确的队列导致的。
