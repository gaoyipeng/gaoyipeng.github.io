Consul 服务注册与发现

Sep 25, 2024
阅读时长: 8 分钟

在微服务开发的过程中，需要引入服务治理功能，实现微服务之间的动态注册与发现。我们本文介绍Consul。

官网地址：

https://developer.hashicorp.com/consul

https://docs.spring.io/spring-cloud-consul/docs/current/reference/html/

一、Consul 简介

Consul是由HashiCorp基于Go语言开发的支持多数据中心的分布式高可用服务发布和注册软件, 采用Raft算法保持服务的一致性, 且支持健康检查，Consul和Eureka的侵入式服务中心不同的是, Consul是以独立的软件形式运行, 对项目侵入性小, 更方便部署。Consul的特性如下：

  • 服务发现：解决在分布式环境中，如何找到可用的服务地址的问题，支持通过DNS和HTTP查询服务地址。
  • 健康检查：定时监控服务是否正常，对于异常的服务会主动下线。
  • 键值存储：配置中心解决方案，是一种key/value存储结构，区别就是key是以目录树结构形式组织的，可以用来存储系统配置信息。
  • 多数据中心：支持多数据中心部署。

1.1 Consul架构

官方架构图：

​ 从官方给出的架构图可以看出，Consul 是支持多数据中心的，图中有两个 DataCenter 通过 Internet 连接，并且只有 Server 可以跨数据中心通信，多数据中心的架构相对复杂一些，这里我们只讨论单数据中心。

下图是单数据中心的部署架构：

​ 在单个数据中心中，Consul 分为 Client 和 Server 两种节点（所有的节点也被称为 Agent），Server 节点保存数据，Client 负责健康检查及转发数据请求到 Server，Client 可以选择和应用部署在同一个节点上；

​ Server 节点有一个 Leader 和多个Follower，Leader 节点会将数据同步到 Follower，官方推荐 Server 的数量是 3 个或者 5 个，在 Leader 挂掉的时候会启动选举机制产生一个新的 Leader，以保证整个集群的正常运转。

​ 集群内数据的读写请求可以直接发到 Server（单节点就是这种情况），也可以通过 Client 使用 RPC 转发到 Server，请求最终会到达 Leader 节点，在允许数据轻微陈旧的情况下，读请求也可以在普通的 Server 节点完成，集群内数据的读写和复制都是通过 TCP 的 8300 端口完成。

​ 可以简单理解为，server是集群数据节点，client是服务节点。

（3）根据uname -m的输出，可以判断系统架构

  • x86_64：表示您的系统是基于AMD64架构（64位）。您应该选择下载AMD64版本。
  • i386或i686：表示您的系统是基于386架构（32位）。您应该选择下载386版本。
  • armv7l或类似的：表示您在使用32位的ARM系统。您应该选择ARM版本。
  • aarch64：表示您的系统是基于ARM64架构（64位）。您应该选择下载ARM64版本。

所以我们下载CentOS AMD64版本。当前最新版本是consul_1.19.2。

二、Consul 单机版部署

机器IP是10.10.82.112。

创建/opt/module/consul 目录，作为 consul 的数据存放目录。在此目录下创建一个启动 consul 的脚本文件 start_consul.sh

[root@hadoop1 consul]# vim /opt/module/consul/start_consul.sh

# agent -server 表示以 server 模式启动服务
# -ui 参数提供一个 web ui 界面
# -client 允许访问的客户端地址，可以是IP，也可以是网段。0.0.0.0不限制
# -bootstrap-expect=1 意思是以集群的方式启动，只不过集群中只有当前这个节点
# -data-dir 目录会用来存放 consul 的数据信息，如服务注册、是否健康等
# -node=consul-01 节点名称
# -datacenter 数据中心名称
# -advertise 往往配置外网IP
# -bind监听地址，表示节点之间通信使用该地址，0.0.0.0不限制IP,本机可以使用localhost、127.0.0.1访问，外部可以用过私有IP、公有IP访问本机consul


nohup /usr/local/bin/consul agent -server -ui -client 0.0.0.0 -bootstrap-expect=1 -data-dir=/opt/module/consul -node=consul-01  -datacenter SH-TMP -bind=0.0.0.0  -log-file=/opt/module/consul/consul.log &

修改执行权限，并启动：

[root@hadoop1 consul]# chmod 755 start_consul.sh
[root@hadoop1 consul]# ./start_consul.sh
[root@hadoop1 consul]# nohup: appending output to ‘nohup.out’

访问：http://10.10.82.112:8500/

3.2.1 Svrver配置文件

在10.10.82.112上创建配置文件目录及日志目录：

[root@hadoop1 consul]# mkdir -p /opt/module/consul.d/consul_data/logs/
[root@hadoop1 consul]# vim /opt/module/consul.d/consul.json
{
"datacenter": "consul-cluster",
"node_name": "consul-svr-01",
"server": true,
"bootstrap_expect": 3,
"data_dir": "/opt/module/consul.d/consul_data",
"log_level": "INFO",
"log_file": "/opt/module/consul.d/consul_data/logs/",
"ui": true,
"bind_addr": "0.0.0.0",
"client_addr": "0.0.0.0",
"retry_join": ["10.10.82.113","10.10.82.114"],
"retry_interval": "10s",
"raft_protocol": 3,
"enable_debug": false,
"rejoin_after_leave": true,
"enable_syslog": false
}

参数说明：

  • datacenter ：数据中心名称
  • node_name ：节点名称
  • server ：是否为 Server 模式，false 为 Client 模式
  • bootstrap_expect ：此标志提供数据中心中预期的服务器数量。要么不提供此值，要么该值必须与集群中的其他服务器一致。如果提供，Consul 将等待直到指定数量的服务器可用为止，然后引导群集。这样可以自动选举最初的领导者。不能与旧 -bootstrap 标志一起使用。该标志需要 -server 模式。
  • data_dir ：Server 节点数据目录
  • -log-file-将所有 Consul 代理日志消息写入文件
  • ui ：是否开启 UI 访问
  • bind_addr ：Server 绑定的 IP，填本机即可
  • client_addr ：作为 Client 绑定的 IP，默认为 127.0.0.1，也就是只有本地服务可以注册，这很明显是不符合需求的
  • retry_join ：尝试加入的其他节点，填写集群中的其他节点 ip 即可
  • raft_protocol ：Raft 协议版本
  • rejoin_after_leave ：允许重新加入集群

3.3 consul集群启停脚本

我们使用root用户在/bin目录下新建myhadoop

[root@hadoop1 bin]# vim myconsul

#!/bin/bash
if [ $# -lt 1 ]; then
   echo "No Args Input..."
   exit 1
fi

case $1 in
   "start")
       echo " =================== 启动 consul 集群 ==================="
       for host in hadoop1 hadoop2 hadoop3 hadoop4 hadoop5; do
           echo =============== $host ===============
           ssh $host "nohup /usr/local/bin/consul agent -config-file=/opt/module/consul.d/consul.json &"
       done
       ;;
   "stop")
       echo " =================== 关闭 consul 集群 ==================="
       for host in hadoop1 hadoop2 hadoop3 hadoop4 hadoop5; do
           echo =============== $host ===============
           ssh $host "/usr/local/bin/consul leave"
       done
       ;;
   "jps")
       echo " =================== 查看 consul 集群服务状态 ==================="
       for host in hadoop1 hadoop2 hadoop3 hadoop4 hadoop5; do
       		echo =============== $host ===============
       		ssh $host  ps -ef | grep consul | grep -v grep|grep -v jps
		done
		;;
   *)
       echo "Input Args Error..."
       ;;
esac

修改文件执行权限

[root@hadoop1 bin]# chmod 755 myconsul
[root@hadoop1 ~]# myconsul stop
[root@hadoop1 ~]# myconsul start

注意：该脚本依赖ssh,我们在前面搭建环境时已经配置。

3 台 Server 和 2 台 Client 上的 Consul 服务都启动后会根据 consul.json 中的配置自动组成一个集群，并且 Server 会通过 Raft 协议在 Server 节点中选举出 leader 节点，可以用如下命令在任意一台机器上查看集群状态：

[root@hadoop1 ~]# /usr/local/bin/consul members

五、服务配置与刷新

consul除了服务注册外，还提供服务配置功能，可以帮组我们解决分布式部署application.yaml太多的问题。

我们可以把一些yaml中的经常会变化的值存在consul中。配置规则如下：

5.1 添加consul配置

5.2 代码配置

我们在cloud-provider新加如下jar包;

<!--SpringCloud consul config-->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-consul-config</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-bootstrap</artifactId>
</dependency>

新建bootstrap.yml

spring:
  application:
    name: cloud-provider
  profiles:
    active: dev
  cloud:
    consul:
      host: 10.10.82.90
      port: 8500
      discovery:
        service-name: ${spring.application.name}
      config:
        enabled: true
        profile-separator: '-'
        format: yaml

application-test.yaml

server:
  port: 8001

  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: GMT+8

application-dev.yaml

server:
  port: 8001

spring:
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: GMT+8

这样程序在启动时会先读取bootstrap.yml文件内容，然后去找consul服务器上/config/cloud-provider-dev/data 下的配置。

我们写一个测试案例;

package com.sxdx.cloudprovider.controller;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.cloud.context.config.annotation.RefreshScope;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping(value = "test")
@RefreshScope
public class TestController {

    @Value("${cloudprovide}")
    private String config;

    @RequestMapping("/getConsulConfig")
    public String getConsulConfig(){
        System.out.println("获取ConsulConfig");
        return config;
    }
}

注意：默认情况下，我们修改完consul的配置，应用是无感的，需要通过springcloud Bus或者@RefreshScope注解的方式刷新配置。
