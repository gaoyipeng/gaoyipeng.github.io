阅读时长: 4 分钟

一、FastDFS介绍及原理

FastDFS 是一个开源的高性能分布式文件系统（DFS）。 它的主要功能包括：文件存储，文件同步和文件访问，以及高容量和负载平衡。主要解决了海量数据存储问题，适合以中小文件（4KB < file_size <500MB）存储。

FastDFS 系统有三个角色：

  • 跟踪服务器(Tracker Server)：Tracker是FastDFS的协调者，负责管理所有的storage server和group，每个storage在启动后会连接Tracker，告知自己所属的group等信息，并保持周期性的心跳，tracker根据storage的心跳信息，建立group==>[storage server list]的映射表。
  • 存储服务器(Storage Server)：Storage server以组（卷，group或volume）为单位，一个group内包含多台storage机器，数据互为备份。卷中的多台存储服务器起到了冗余备份和负载均衡的作用。存储空间以group内容量最小的storage为准，所以建议group内的多个storage尽量配置相同，以免造成存储空间的浪费。storage接受到写文件请求时，会根据配置好的规则，选择其中一个存储目录来存储文件。为了避免单个目录下的文件数太多，在storage第一次启动时，会在每个数据存储目录里创建2级子目录，每级256个，总共65536个文件目录，新写的文件会以hash的方式被路由到其中某个子目录下，然后将文件数据直接作为一个本地文件存储到该目录中。存储系统由一个或多个卷组成，卷与卷之间的文件是相互独立的，所有卷的文件容量累加就是整个存储系统中的文件容量。当存储空间不足时，可以动态添加group，只需要增加一台或多台服务器，并将它们配置为一个新的组，即可扩大存储系统的容量。当你的某个应用或者模块（对应的 group）的并发过高的时候，可以直接在 group 中增加若干个 Storage 来实现负载均衡。
  • 和客户端(Client)：一般指我们的应用服务。

tracker 和 storage 其实都是 fastdfs，只不过启动时通过不同的配置文件启动，所扮演的角色不同而已。也就是说，安装 tracker 和 storage 就是在安装 fastdfs，然后通过每个角色具体的配置文件启动即可。

二、文件上传

当客户端发起一个文件上传请求时，FastDFS通过以下步骤来进行文件存储：

1、选择存储的group（tracker.conf）：当tracker接收到upload file的请求时，会为该文件分配一个可以存储该文件的group，group选择规则有以下几种：

（1）、Round robin：所有的group间轮询 
（2）、Specified group：指定某一个确定的group 
（3）、Load balance：负载均衡，剩余存储空间多的group优先

2、选择Storage Server（tracker.conf）：当选定group后，tracker会在group内选择一个storage server给客户端，storage选择的规则：

（1）、Round robin:在group内的所有storage间轮询 
（2）、First server ordered by ip:按ip排序 
（3）、First server ordered by priority:按优先级排序（优先级在storage上配置）

3、选择storage path (storage.conf)：当分配好storage server后，客户端将向storage发送写文件请求，storage.conf将会为文件分配一个数据存储目录，目录选择的规则：

（1）、Round robin，多个存储目录间轮询 
（2）、剩余存储空间最多的优先

4、生成Fileid**：当文件存储到某个子目录后，即认为该文件存储成功，接下来会为该文件生成一个文件名，文件名由group、存储目录、两级子目录、fileid、文件后缀名（由客户端指定，主要用于区分文件类型）拼接而成（示例：group4/M00/01/0D/CgEiFVpBpkKAdgd5AAr7iauffrw964.pdf）。

5、文件同步：客户端将文件写至group内一个storage server即认为写文件成功，storage server写完文件后，会由后台线程将文件同步至同group内其他的storage server。每个storage写文件后，同时会写一份binlog，binlog里不包含文件数据，只包含文件名等元信息，这份binlog用于后台同步，storage会记录向group内其他storage同步的进度，以便重启后能接上次的进度继续同步（进度以时间戳的方式进行记录，所以最好能保证集群内所有server的时钟保持同步）。storage的同步进度会作为元数据的一部分汇报到tracker上，tracke在选择读storage的时候会以同步进度作为参考。

三、文件下载

客户端使用storage生成的Fileid即可访问到该文件。在downloadfile时客户端可以选择任意tracker server。发送download请求给某个tracker，必须带上文件名信息，tracke从文件名中解析出文件的group、大小、创建时间等信息，然后为该请求选择一个storage用来服务读请求。

由于group内的文件同步时在后台异步进行的，所以有可能出现在读到时候，文件还没有同步到某些storage server上，为了尽量避免访问到这样的storage，tracker按照如下规则选择group内可读的storage。

 1、该文件上传到的源头storage - 源头storage只要存活着，肯定包含这个文件，源头的地址被编码在文件名中。

目前成熟的解决方案是：使用 fastdfs-nginx-module，它可以重定向文件链接到源服务器进行获取，避免客户端由于复制延迟导致的文件无法访问的错误。当然如果相信storage server的后台同步效率，也可以不使用该模块。

4.4、软件安装

4.4.1 解压并编译安装 (libfastcommon-V1.0.7、fastdfs-V5.05)

[root@host-192-168-3-100 libfastcommon-V1.0.7]# ./make.sh
[root@host-192-168-3-100 libfastcommon-V1.0.7]# ./make.sh install
[root@host-192-168-3-100 fastdfs-V5.05]# ./make.sh
[root@host-192-168-3-100 fastdfs-V5.05]# ./make.sh installe

libfastcommon-V1.0.7 编译安装

fastdfs-V5.05 编译安装

fastdfs 默认安装在以下位置：

  • /usr/bin：可执行文件
  • /etc/fdfs：配置文件
  • /etc/init.d：主程序代码
  • /usr/include/fastdfs：插件组

/etc/fdfs目录下生成三个文件：

  • client.conf.sample：客户端的配置文件，测试用。
  • storage.conf.sample：存储器的配置文件。
  • tracker.conf.sample：跟踪器的配置文件。

我们进行拷贝来做后续配置使用。

另外，再将/usr/local/fastdfs/fastdfs-V5.05/conf/文件夹中的http.conf和mime.types拷贝到 /etc/fdfs/中。

  • http.conf：http访问配置文件，主要是配合nginx做相关的访问配置
  • mime.types：媒体类型配置文件，为了让服务器对应处理，也是配合nginx

4.4.2 创建初始化目录

1）配置tracker所需的base_path目录: mkdir -p /data/FASTDFS/fastdfs_tracker
2）配置storage所需的日志目录: mkdir -p /data/FASTDFS/fastdfs_storage_info
3）配置storage所需的存储文件目录: mkdir -p /data/FASTDFS/fastdfs_storage_data
4）配置client的存储文件目录: mkdir -p /data/FASTDFS/client

4.4.3配置Tracker

编辑2台服务器的 tracker.conf 配置文件，修改以下内容：

# 允许访问 tracker 服务器的 IP 地址，为空则表示不受限制
bind_addr =

# tracker 服务监听端口
port = 22122

# tracker 服务器的运行数据和日志的存储父路径（需要提前创建好）
base_path = /data/FASTDFS/fastdfs_tracker

# tracker 服务器 HTTP 协议下暴露的端口
http.server_port = 8080

设置软连接，这样我们就可以采用熟悉的系统服务启动方式

ln -s /usr/bin/fdfs_trackerd /usr/local/bin
ln -s /usr/bin/stop.sh /usr/local/bin
ln -s /usr/bin/restart.sh /usr/local/bin

配置完成，启动tracker服务：

启动方式1：

# 启动 tracker 服务
service fdfs_trackerd start

常用命令：

# 启动 tracker 服务
service fdfs_trackerd start
# 查看 tracker 服务状态
service fdfs_trackerd status
# 重启 tracker 服务
service fdfs_trackerd restart
# 停止 tracker 服务
service fdfs_trackerd stop

启动方式2：脚本启动

启动tracker服务器: /etc/init.d/fdfs_trackerd start
停止tracker服务器: /etc/init.d/fdfs_trackerd stop

启动方式3：也可以指定配置文件来启动 tracker服务：

#由于fdfs_trackerd在/usr/bin 目录下，所以我们在任意目录下都可以使用它

[root@host-192-168-3-97 fdfs]# fdfs_trackerd /etc/fdfs/tracker.conf start
[root@host-192-168-3-97 fdfs]# ps -ef|grep fdfs
root      2076     1  0 15:03 ?        00:00:00 fdfs_trackerd /etc/fdfs/tracker.conf start
root      2084 26689  0 15:03 pts/0    00:00:00 grep fdfs

4.4.4 配置Storage

编辑2台服务器的 storage.conf 配置文件，修改以下内容：

# storage 组名/卷名，默认为 group1
group_name = group1

# 允许访问 storage 服务器的 IP 地址，为空则表示不受限制
bind_addr =

# storage 服务器的运行数据和日志的存储父路径（需要提前创建好）
base_path = /data/FASTDFS/fastdfs_storage_info

# storage 服务器中客户端上传的文件的存储父路径（需要提前创建好）
store_path0 = /data/FASTDFS/fastdfs_storage_data

# storage 服务器 HTTP 协议下暴露的端口
http.server_port = 8888

# tracker 服务器的 IP 和端口
tracker_server = 10.10.81.74:22122
tracker_server = 10.10.81.75:22122

设置软连接，这样我们就可以采用熟悉的系统服务启动方式

ln -s /usr/bin/fdfs_storaged /usr/local/bin

配置完成，启动storage服务：

service fdfs_storaged start

　查看 /data/FASTDFS/fastdfs_storage_data/data 目录可以看到 Storage 服务器创建了 65536 个文件夹用于存储客户端上传的文件。

4.5、客户端操作

FastDFS 向使用者提供基本文件访问接口，比如 upload、download、append、delete 等，以客户端库的方式提供给用户使用。在 Tracker 服务器的机器上编辑 client.conf 配置文件。

# client 客户端的运行数据和日志的存储父路径（需要提前创建好）
base_path = /data/FASTDFS/client

# tracker 服务器的 IP 和端口
tracker_server = 10.10.81.74:22122
tracker_server = 10.10.81.75:22122

4.5.1 上传

4.5.1.1 上传方式1：fdfs_upload_file

格式：fdfs_upload_file /etc/fdfs/client.conf filename

新建文件，并输入任意内容，并上传，可以看到返回的文件信息。

[root@host-192-168-3-100 client]# vim aa.text

[root@host-192-168-3-100 client]# fdfs_upload_file /etc/fdfs/client.conf aa.text
group1/M00/00/00/wKgDYWSJdw-AIrXPAAAAGZBcoxk89.text

文件上传成功以后，会返回该文件在 Storage 服务器中的存储位置及随机生成的文件名。其中 group1 表示 Storage 组名/卷名，M00 是一个虚拟目录，表示 /fastdfs/storage/store/data/ 真实路径中的 data 目录。

由于2台服务器storage同属于group1。所以2台服务器间同group1下的storage，数据应该是同步的。但在实际测试过程中，上传文件后，在10.10.81.74的存储路径下马上可以看到上传的文件，但是在10.10.81.75同目录下，将近半小时候才看到同步文件。storage 2一直是WAIT_SYNC状态，直到同步完成后才变为ACTIVE状态。

4.5.1.2 上传方式2：fdfs_test upload

格式：fdfs_test /etc/fdfs/client.conf upload filename

通过 fdfs_test 的方式上传文件，会返回该文件上传成功以后详细的相关信息。

  • group_name：Storage 组名/卷名
  • remote_filename：上传成功文件的存储路径及文件名
  • source_ip address：上传成功文件所在的 Storage 服务器的 IP 地址
  • file timestamp：上传成功文件时的时间戳
  • file size：上传成功文件的文件大小
  • example file url：上传成功文件的 url 地址，配合 Nginx 可以直接访问
  • storage_upload_slave_by_filename：FastDFS 的文件主/从特性，由主文件产生从文件

查看 Storage 服务器发现该文件已成功上传。后缀为 jpg-m 的文件存放了上传成功文件的元数据信息。

4.5.2 下载

客户端 upload file 成功以后，会拿到一个 Storage 生成的文件名，接下来客户端根据这个文件名即可访问到该文件。跟 upload file 一样，在 download file 时客户端可以选择任意 Tracker Server。客户端发送 download 请求给某个 Tracker，必须带上文件名信息，Tracke 从文件名中解析出该文件的 group、大小、创建时间等信息，然后为该请求选择一个 Storage 用于提供读取服务。

4.5.2.1 下载方式1：fdfs_download_file

我们下载上一步上传的文件：remote_filename=M00/00/00/wKgDYWSKbCWAaL47AAAAMMyxo0k123.txt

格式：fdfs_download_file /etc/fdfs/client.conf group_name/remote_filename

4.5.2.2 下载方式2：fdfs_test download

格式：fdfs_test /etc/fdfs/client.conf download group_name remote_filename

五、扩展Group2

目前我们的部署架构只有一个group1，group有2个storage节点。下面再添加一个group2。

首先我们分别在10.10.81.74、10.10.81.75的/etc/fdfs目录下，将storage.conf文件拷贝一份出来，作为group2的配置文件。

[root@host-192-168-3-97 fdfs]# cp storage.conf storage1.conf

修改内容如下：

# storage 组名/卷名，默认为 group1
group_name = group2

#  storage 端口信息，要和group1区分开来
port=23001

# 允许访问 storage 服务器的 IP 地址，为空则表示不受限制
bind_addr =

# storage 服务器的运行数据和日志的存储父路径（需要提前创建好）
base_path = /data/FASTDFS/fastdfs_storage_info1

# storage 服务器中客户端上传的文件的存储父路径（需要提前创建好）
store_path0 = /data/FASTDFS/fastdfs_storage_data1

# storage 服务器 HTTP 协议下暴露的端口
http.server_port = 8888

# tracker 服务器的 IP 和端口
tracker_server = 10.10.81.74:22122
tracker_server = 10.10.81.75:22122

注意：base_path和base_path0路径需要提前创建好。

[root@host-192-168-3-100 fdfs]# mkdir /data/FASTDFS/fastdfs_storage_info1
[root@host-192-168-3-100 fdfs]# mkdir /data/FASTDFS/fastdfs_storage_data1

然后我们指定配置文件启动storage1.

fdfs_storaged /etc/fdfs/storage1.conf start

我们查看当前集群状态就可以看到新的group2的信息了：

[root@host-192-168-3-100 fdfs]# fdfs_monitor /etc/fdfs/storage.conf

此时我们测试一下附件上传，Tracker选择group的规则默认是Load balance：负载均衡，我们修改其中一个Trackerd.conf规则为轮询。验证附件上传。

然后重启tracker服务：

#  service fdfs_trackerd restart

上传文件，可以看到分别上传到了group1和group2上面。

5.1、解决storage server一直处于wait_sync状态问题

此时查看10.10.81.75的group1下是否同步了数据，但是等待20分钟依然没有同步。

解决方案是：如果遇到storage状态是WAIT_SYNC状态就把storage从集群中删除。然后在重新启动storage服务（未验证重启）。我在删除后，没有重新启动，再次查看就可以看到数据同步了。

[root@host-192-168-3-100 00]# fdfs_monitor /etc/fdfs/storage1.conf delete group2 10.10.81.75

而且监控信息也变为了ACTIVE，后续上传新文件，也未出现一直不同步的问题。
